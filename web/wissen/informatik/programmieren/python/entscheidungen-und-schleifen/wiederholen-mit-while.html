Worum es geht:

Viele Aufgaben bestehen darin, denselben Schritt so lange zu wiederholen, bis ein Ziel erreicht ist: so lange rechnen, bis ein Ergebnis genau genug ist, so lange warten, bis ein Tee abgekühlt ist. In Kapitel 1 musste man dafür die Pfeiltaste drücken, Durchgang für Durchgang. Dieser Abschnitt führt die Anweisung ein, die das selbst erledigt, und zeigt die zwei häufigsten Gründe, warum sie nicht aufhört.

Die while-Schleife#

Eine Anweisung, die einen Block wiederholt, heißt Schleife. Die einfachste Schleife wiederholt ihren Block, solange eine Bedingung gilt.

Ein Pfeil zurück. Im Flussdiagramm sieht eine solche Schleife aus wie eine Entscheidung, deren Ja-Weg wieder nach oben zur Raute führt (Abb. 4). Nach jeder Ausführung des Blocks wird die Frage neu gestellt; erst ein Nein führt aus dem Kreis heraus.

Definition 3.1 (while-Schleife)

Eine while-Schleife hat die Form

while Bedingung: Block

Python prüft den Wahrheitswert der Bedingung. Ist er True, führt es den Block aus und kehrt danach zur Kopfzeile zurück, um die Bedingung erneut zu prüfen. Ist er False, geht es mit der ersten Zeile nach dem Block weiter. Eine einzelne Ausführung des Blocks heißt Durchlauf. Die Bedingung wird vor jedem Durchlauf geprüft; ist sie schon beim ersten Mal falsch, läuft der Block kein einziges Mal.

Beispiel

Ein Zähler steuert die Zahl der Durchläufe:

zaehlen.pyPython
# Drei Durchläufe, gesteuert von einem Zähler
zaehler = 1
while zaehler <= 3:
    print("Durchlauf", zaehler)
    zaehler = zaehler + 1
print("fertig, zaehler =", zaehler)
LinuxKonsole
$ python3 zaehlen.py
Durchlauf 1
Durchlauf 2
Durchlauf 3
fertig, zaehler = 4

Verfolgt man das Skript Prüfung für Prüfung, sieht man, warum am Ende zaehler = 4 dasteht:

Prüfungzaehlerzaehler <= 3was passiert
11TrueDurchlauf 1, danach zaehler = 2
22TrueDurchlauf 2, danach zaehler = 3
33TrueDurchlauf 3, danach zaehler = 4
44FalseSchleife endet

Drei Durchläufe brauchen vier Prüfungen: Die letzte Prüfung ist die, die falsch ausfällt.

⁠Kurz gesagt: while Bedingung: wiederholt den Block, solange die Bedingung vor dem Durchlauf wahr ist.

Die Endlosschleife#

Eine while-Schleife endet nur, wenn ihre Bedingung irgendwann falsch wird. Dazu muss der Block etwas verändern, wovon die Bedingung abhängt.

Ein Programm, das hängt. Ändert der Block nichts an der Bedingung, prüft Python immer wieder dieselbe wahre Bedingung. Von außen sieht man oft nur, dass das Programm nicht fertig wird.

Definition 3.2 (Endlosschleife)

Eine Endlosschleife ist eine Schleife, deren Bedingung nie falsch wird. Ein Programm in einer Endlosschleife bricht man mit Strg+C ab, also mit gedrückter Steuerungstaste und der Taste C. Python beendet das Programm dann mit der Ausnahme KeyboardInterrupt und einem Traceback (Kapitel 1, Abschnitte 6.3 und 6.4).

Beispiel

Das Skript soll $1+2+3$ addieren, aber der Zähler wird nie erhöht:

endlos.pyPython
# Summe 1 + 2 + 3, aber der Zähler wird nie erhöht
zaehler = 1
summe = 0
while zaehler <= 3:
    summe = summe + zaehler
print("Summe:", summe)

Gestartet, gibt es nichts aus. Nach etwa einer Sekunde ist hier Strg+C gedrückt worden. Das Linux-Terminal zeigt den Tastendruck als ^C:

LinuxKonsole
$ python3 endlos.py
^CTraceback (most recent call last):
  File "/home/student/python-kurs/endlos.py", line 5, in <module>
    summe = summe + zaehler
    ^^^^^
KeyboardInterrupt
Windows (PowerShell)Konsole
PS> py endlos.py
Traceback (most recent call last):
  File "C:\Users\student\python-kurs\endlos.py", line 4, in <module>
    while zaehler <= 3:
          ^^^^^^^^^^^^
KeyboardInterrupt

Die Ortszeile nennt die Zeile, in der das Programm gerade war, als die Unterbrechung ankam. In diesen Versuchen war das unter Linux stets Zeile 5 und unter Windows stets Zeile 4; beide liegen in der Schleife, und welche es trifft, hängt vom Betriebssystem und vom Zeitpunkt ab. Die letzte Zeile, print("Summe:", summe), wurde nie erreicht. Behoben ist der Fehler mit der Zeile zaehler = zaehler + 1 im Block. Im interaktiven Modus bricht Strg+C ebenso eine laufende Schleife ab; danach erscheint wieder >>>, und die Sitzung geht weiter.

⁠Kurz gesagt: Ändert der Block nichts, wovon die Bedingung abhängt, läuft die Schleife endlos; Strg+C bricht sie mit KeyboardInterrupt ab.

HintergrundWie Strg+C ein laufendes Programm erreicht

Die Tastenkombination fängt das Terminal ab, nicht Python. Das Betriebssystem benachrichtigt daraufhin das laufende Programm, unter Linux mit einem Signal, unter Windows über eine eigene Meldung an alle Programme des Konsolenfensters. CPython hat dafür eine kleine Routine angemeldet. Sie unterbricht die laufende Rechnung nicht sofort, sondern setzt nur eine Merkmarke. Die Interpreterschleife, die den Bytecode Befehl für Befehl abarbeitet (Kapitel 1, Abschnitt 2.4), sieht bei passender Gelegenheit nach dieser Marke, etwa vor dem nächsten Befehl, und löst dann in der gerade laufenden Zeile die Ausnahme KeyboardInterrupt aus. Deshalb kann Python an jeder Stelle eines Python-Programms unterbrochen werden, aber nicht mitten in einer einzelnen, lange dauernden Rechnung, die vollständig im C-Code von Python abläuft: Die Unterbrechung wirkt erst, wenn diese fertig ist.

Die Gleitkomma-Falle#

Eine Schleife soll in Schritten von 0,1 von 0 bis 1 zählen. Die naheliegende Bedingung „solange $x\ne1$“ ist eine Falle, und der Grund ist aus Kapitel 2 bekannt.

Die 1 wird übersprungen. Damit die Falle nicht wirklich endlos läuft, bekommt das Skript eine Notbremse: Nach 12 Durchläufen ist in jedem Fall Schluss.

gleitkomma.pyPython
# Zehnmal 0.1 addieren und auf genau 1.0 warten, mit einer Notbremse nach 12 Durchläufen
x = 0.0
durchlauf = 0
while x != 1.0 and durchlauf < 12:
    x = x + 0.1
    durchlauf = durchlauf + 1
    print(durchlauf, x)
LinuxKonsole
$ python3 gleitkomma.py

4 0.4

8 0.7999999999999999

Nach zehn Additionen ist x nicht 1.0, sondern 0.9999999999999999; nach der elften ist es schon darüber. Die Bedingung x != 1.0 ist nie falsch geworden, ohne Notbremse liefe die Schleife endlos.

Mit < statt !=. Die Bedingung x < 1.0 wird zwar irgendwann falsch, aber einen Durchlauf zu spät, denn auch 0.9999999999999999 ist kleiner als 1:

gleitkomma_kleiner.pyPython
# Mit < statt != endet die Schleife, aber erst einen Durchlauf zu spät
x = 0.0
durchlauf = 0
while x < 1.0:
    x = x + 0.1
    durchlauf = durchlauf + 1
print(durchlauf, x)
LinuxKonsole
$ python3 gleitkomma_kleiner.py

Die Abhilfe: ganzzahlig zählen. Sicher ist eine Schleife, die eine ganze Zahl zählt und den float in jedem Durchlauf neu aus ihr berechnet. Ganze Zahlen sind exakt (Kapitel 2, Abschnitt 2.1), und die Bedingung k < 10 wird genau nach dem zehnten Durchlauf falsch:

gleitkomma_zaehler.pyPython
# Abhilfe: ganzzahlig zählen und den float in jedem Durchlauf neu ausrechnen
k = 0
while k < 10:
    k = k + 1
    x = k / 10
print(k, x)

$ python3 gleitkomma_zaehler.py

⁠Kurz gesagt: Eine Schleife nie mit != oder == auf einen float warten lassen; ganzzahlig zählen und den float daraus berechnen.

HintergrundWarum x = x + 0.1 die 1 nicht trifft, k / 10 aber schon

Der gespeicherte Wert von 0.1 ist etwas größer als 0,1, und jede Addition wird auf den nächsten float gerundet (Kapitel 2, Abschnitt 5.1). Diese Rundungen fallen mal nach oben, mal nach unten aus. Bei 0.1 + 0.2 fällt sie nach oben, sichtbar als 0.30000000000000004. Bei späteren Schritten fällt sie nach unten, etwa von 0.7 zu 0.7999999999999999. Nach zehn Schritten bleibt eine Summe, die eine kleinste Stufe unter 1 liegt. Die Fehler häufen sich, weil jedes Zwischenergebnis den Fehler aller vorigen mitbringt.

k / 10 ist dagegen eine einzige Rechnung mit zwei exakten ganzen Zahlen. Sie wird nur einmal gerundet, auf den float, der $k/10$ am nächsten liegt. Das ist genau der float, den Python auch für die Schreibweise 0.3 oder 1.0 speichert. Mit dem Zähler gibt es also keinen aufgehäuften Fehler, sondern in jedem Durchlauf nur den unvermeidlichen Darstellungsfehler einer einzelnen Zahl.

Anwendung: Wie lange ein Tee zum Abkühlen braucht#

Ein frisch aufgegossener Tee hat 90 °C, das Zimmer hat 20 °C. Wie in Kapitel 2, Abschnitt 8.2 schrumpft der Temperaturunterschied zwischen Tee und Zimmer näherungsweise wie eine Exponentialfunktion. Die Temperatur des Tees ist dann

$$\textcolor{#1b7f4a}{T(t)}\textcolor{#15633a}{=}\textcolor{#c2410c}{T_\mathrm Z+(T_0-T_\mathrm Z)\,\mathrm{e}^{-t/\tau}}$$

mit der Zimmertemperatur $T_\mathrm Z$, der Anfangstemperatur $T_0$ und einer Zeitkonstanten $\tau$, die von Tasse, Menge und Luftzug abhängt; hier ist sie 20 min. Wie lange dauert es, bis der Tee auf 60 °C abgekühlt ist?

Für eine Schleife zerlegt man die Zeit in kleine Schritte $\Delta t$. Wegen $\textcolor{#1b7f4a}{\mathrm{e}^{-(t+\Delta t)/\tau}}\textcolor{#15633a}{=}\textcolor{#c2410c}{\mathrm{e}^{-t/\tau}\cdot\mathrm{e}^{-\Delta t/\tau}}$ wird der Temperaturunterschied $T-T_\mathrm Z$ in jedem Schritt mit demselben Faktor $\mathrm{e}^{-\Delta t/\tau}$ multipliziert. Wie viele Schritte es bis 60 °C braucht, weiß man vorher nicht; die Schleife läuft, solange der Tee noch wärmer ist.

tee.pyPython
# Ein Tee kühlt im Zimmer ab: Wann hat er nur noch 60 Grad?
import math
tau = 20.0              # Zeitkonstante in min
dt = 0.1                # Zeitschritt in min
zimmer = 20.0           # Zimmertemperatur in Grad
tee = 90.0              # Temperatur des Tees zu Beginn in Grad
faktor = math.exp(-dt / tau)
schritte = 0
while tee > 60.0:
    tee = zimmer + (tee - zimmer) * faktor
    schritte = schritte + 1
print("Schritte:", schritte)
print(f"Zeit: {schritte * dt:.1f} min, Temperatur: {tee:.2f} Grad")
print(f"Formel tau * ln(70/40): {tau * math.log(70 / 40):.2f} min")

$ python3 tee.py

Aus $\textcolor{#1b7f4a}{20+70\,\mathrm{e}^{-t/\tau}}\textcolor{#15633a}{=}\textcolor{#c2410c}{60}$ folgt $\textcolor{#1b7f4a}{\mathrm{e}^{-t/\tau}}\textcolor{#15633a}{=}\textcolor{#c2410c}{40/70}$ und $\textcolor{#1b7f4a}{t}\textcolor{#15633a}{=}\textcolor{#c2410c}{\tau\ln(70/40)}\textcolor{#15633a}{\approx}\textcolor{#c2410c}{11{,}19}$ min. Die Schleife findet den ersten Zeitschritt, nach dem der Tee höchstens 60 °C hat: Nach 111 Schritten, also 11,1 min, ist er noch knapp darüber, nach 112 Schritten darunter. Ihr Ergebnis liegt deshalb höchstens einen Zeitschritt hinter dem exakten Wert. Die Zeit rechnet das Skript als schritte * dt aus dem ganzzahligen Zähler, nicht durch fortgesetztes Addieren von dt.

⁠Kurz gesagt: while ist die richtige Schleife, wenn man die Zahl der Durchläufe vorher nicht kennt, sondern nur das Ziel.

Aufgabe 13 ★★ Ein Getränk wird warm

Eine Flasche Saft kommt mit 6 °C aus dem Kühlschrank in ein Zimmer mit 21 °C. Ihre Temperatur ist näherungsweise $\textcolor{#1b7f4a}{T(t)}\textcolor{#15633a}{=}\textcolor{#c2410c}{T_\mathrm Z-(T_\mathrm Z-T_0)\,\mathrm{e}^{-t/\tau}}$, mit denselben Bezeichnungen wie beim Tee in Unterabschnitt 3.4. Zeige, dass in jedem Zeitschritt $\textcolor{#1b7f4a}{T_\mathrm{neu}}\textcolor{#15633a}{=}\textcolor{#c2410c}{T_\mathrm Z-(T_\mathrm Z-T_\mathrm{alt})\,\mathrm{e}^{-\Delta t/\tau}}$ gilt. Schreibe damit ein Skript, das mit $\textcolor{#1b7f4a}{\tau}\textcolor{#15633a}{=}\textcolor{#c2410c}{30}$ min und $\textcolor{#1b7f4a}{\Delta t}\textcolor{#15633a}{=}\textcolor{#c2410c}{0{,}1}$ min die Schritte zählt, bis die Flasche 90 % des Wegs zur Zimmertemperatur geschafft hat, also 19,5 °C erreicht, und vergleiche mit $\tau\ln10$.

Lösung

Aus $\textcolor{#1b7f4a}{T(t)}\textcolor{#15633a}{=}\textcolor{#c2410c}{T_\mathrm Z-(T_\mathrm Z-T_0)\,\mathrm{e}^{-t/\tau}}$ folgt $\textcolor{#1b7f4a}{T_\mathrm Z-T(t)}\textcolor{#15633a}{=}\textcolor{#c2410c}{(T_\mathrm Z-T_0)\,\mathrm{e}^{-t/\tau}}$, und damit

$$\textcolor{#1b7f4a}{T(t+\Delta t)}\textcolor{#15633a}{=}\textcolor{#c2410c}{T_\mathrm Z-(T_\mathrm Z-T_0)\,\mathrm{e}^{-t/\tau}\,\mathrm{e}^{-\Delta t/\tau}}\textcolor{#15633a}{=}\textcolor{#c2410c}{T_\mathrm Z-\bigl(T_\mathrm Z-T(t)\bigr)\,\mathrm{e}^{-\Delta t/\tau}.}$$

Der Abstand zur Zimmertemperatur nimmt also in jedem Schritt um denselben Faktor ab, wie beim Tee.

erwaermen.pyPython
# Eine Flasche aus dem Kühlschrank erwärmt sich im Zimmer: Wann hat sie 90 % des Wegs geschafft?
import math
tau = 30.0              # Zeitkonstante in min
dt = 0.1                # Zeitschritt in min
zimmer = 21.0           # Zimmertemperatur in Grad
flasche = 6.0           # Temperatur der Flasche zu Beginn in Grad
faktor = math.exp(-dt / tau)
schritte = 0
while flasche < 19.5:   # 90 % des Wegs von 6 auf 21 Grad
    flasche = zimmer - (zimmer - flasche) * faktor
    schritte = schritte + 1
print(f"Schritte: {schritte}, Zeit: {schritte * dt:.1f} min, Temperatur: {flasche:.2f} Grad")
print(f"Formel tau * ln(10): {tau * math.log(10):.2f} min")

Aus $\textcolor{#1b7f4a}{(T_\mathrm Z-T_0)\,\mathrm{e}^{-t/\tau}}\textcolor{#15633a}{=}\textcolor{#c2410c}{0{,}1\,(T_\mathrm Z-T_0)}$ folgt $\textcolor{#1b7f4a}{t}\textcolor{#15633a}{=}\textcolor{#c2410c}{\tau\ln10}\textcolor{#15633a}{\approx}\textcolor{#c2410c}{69{,}08}$ min. Zusammenfassung

Begriffe
  • Schleife – Eine Anweisung, die einen Block wiederholt, heißt Schleife.
  • while-Schleife – Eine while-Schleife hat die Form …
  • Durchlauf – Eine einzelne Ausführung des Blocks heißt Durchlauf.
  • Endlosschleife – Eine Endlosschleife ist eine Schleife, deren Bedingung nie falsch wird.
Zusammenhänge
  • Zu „Die while-Schleife“: while Bedingung: wiederholt den Block, solange die Bedingung vor dem Durchlauf wahr ist.
  • Zu „Die Endlosschleife“: Ändert der Block nichts, wovon die Bedingung abhängt, läuft die Schleife endlos; Strg+C bricht sie mit KeyboardInterrupt ab.
  • Zu „Die Gleitkomma-Falle“: Eine Schleife nie mit != oder == auf einen float warten lassen; ganzzahlig zählen und den float daraus berechnen.
  • Zu „Anwendung: Wie lange ein Tee zum Abkühlen braucht“: while ist die richtige Schleife, wenn man die Zahl der Durchläufe vorher nicht kennt, sondern nur das Ziel.
