What this stage is about:

A program should ask for values and output results neatly formatted. This section shows how to calculate with strings, insert numbers into text with a chosen format, read input, convert text and numbers into each other, and round. At the end, you build a small running pace calculator.

Concatenating and repeating strings#

Chapter 1 introduced the string as a value made of text (Chapter 1, Section 4.6); its type is called str. You can do some calculating with text, too: join pieces together, build lines out of dashes, determine the length.

Definition 10.1 (Operators and length of strings)

For strings, + means joining end to end, called concatenation: "Regen" + "schirm" is "Regenschirm" (German for “umbrella”). * with an int repeats the string. The built-in function len returns the number of characters.

Example

Concatenating, repeating, counting:

Terminal
>>> "Regen" + "schirm"
'Regenschirm'
>>> "ha" * 3
'hahaha'
>>> "-" * 20
'--------------------'
>>> len("Regen")
5
>>> len("Größe")
5
>>> len("")
0
>>> "4" + "2"
'42'

"" is the empty string, with zero characters. "4" + "2" gives the text '42', not the number 6: for str, + means concatenation, no matter what is inside the string.

⁠In short: For strings, + concatenates, * repeats, and len counts the characters.

The f-string#

print("Preis pro kg in Euro:", kilopreis) prints 16 digits where two decimal places are enough. For neat output, you want to put numbers in the middle of a text and decide how many digits appear.

A form with blanks. You write the text down once and leave blanks; each blank receives a calculated value, in the desired form.

Definition 10.2 (f-string)

An f-string is a string with an f before the opening quotation mark. Every expression in curly braces {...} is evaluated, and its value is inserted as text at this position.

After the expression, separated by a colon, there can be a format specifier. It determines how the value appears as text:

Format specifierMeaningExample and result
.2f2 decimal placesf"{3.14159:.2f}" gives 3.14
.3escientific notationf"{0.0125:.3e}" gives 1.250e-02
8.3fat least 8 characters widef"{3.14159:8.3f}" gives 3.142
5dinteger, 5 characters widef"{42:5d}" gives 42
,.2fwith thousands separatorf"{1234567.891:,.2f}" gives 1,234,567.89
.1%as a percentagef"{0.256:.1%}" gives 25.6%
08bbinary with 8 digitsf"{19:08b}" gives 00010011
xhexadecimalf"{255:x}" gives ff

If the expression is followed by an equals sign, f"{gewicht=}", Python inserts the expression itself, an = and the value; this is handy for looking at intermediate values. The format specifiers are the same as for the function format from subsection 3.4. As in all Python output, the decimal point is written as a point and the thousands separator as a comma.

Example

Lines for the receipt at the cheese counter, with the price per kilogram and the weight:

Terminal
>>> kilopreis = 26.4
>>> gewicht = 0.125
>>> f"Gewicht = {gewicht} kg, also {gewicht * 1000:.1f} g"
'Gewicht = 0.125 kg, also 125.0 g'
>>> f"Preis = {kilopreis * gewicht:.2f} Euro"
'Preis = 3.30 Euro'
>>> f"Pro Gramm: {kilopreis / 1000:.3e} Euro"
'Pro Gramm: 2.640e-02 Euro'
>>> f"{gewicht=}"
'gewicht=0.125'
>>> print(f"Zu zahlen: {kilopreis * gewicht:.2f} Euro")
Zu zahlen: 3.30 Euro

The interactive mode displays an f-string as a string in single quotes; only print outputs the bare text.

The stored value of 0.1, ready-made. In subsection 4.6, the calculation with $5^{55}$ by hand gave the 55 decimal places of the stored value of 0.1. With a format specifier, you get them directly:

Terminal
>>> f"{0.1:.20f}"
'0.10000000000000000555'
>>> f"{0.1:.55f}"
'0.1000000000000000055511151231257827021181583404541015625'

The same digits as by hand. A format specifier rounds only the display; the value of the object stays as it is.

⁠In short: An f-string inserts the values in {...} into a text; after the colon, a format specifier determines the digits and the form.

Input with input#

So far, all values have been in the source code. But a calculator for everyday use should ask for the numbers it calculates with.

Definition 10.3 (input)

The built-in function input writes the text in its parentheses to the terminal as a question, waits until the user types a line and presses Enter, and returns this line as a string, without the Enter.

Example

In interactive mode, the question appears (here: the number of guests), and after it you type the answer, here 5:

Terminal
>>> gaeste = input("Anzahl Gäste: ")
Anzahl Gäste: 5
>>> gaeste
'5'
>>> type(gaeste)
<class 'str'>
>>> gaeste * 2
'55'

input always returns a string, even if you type in a number. That is why gaeste * 2 repeats the text instead of calculating. Calculating with an input requires a further step.

⁠In short: input asks for a line and returns it as a str.

Type conversion#

The text '5' should become the number 5, the number 42 the text '42'. Python never converts on its own (subsection 1.2); you have to ask for it explicitly.

Definition 10.4 (Type conversion)

The functions int, float and str create a new object from a value, with the type of their name. This is called type conversion.

  • int(text) and float(text) read a number from a string; spaces at the edges are allowed. If the text does not fit, they raise a ValueError.

  • int(x) turns a float into an integer by cutting off the decimal places, that is, by rounding toward zero.

  • str(x) returns the text that print would output for $x$.

Example

Conversions that succeed, and two that fail:

Terminal
>>> int("42")
42
>>> int(" 42 ")
42
>>> float("4.2")
4.2
>>> float("1e3")
1000.0
>>> int("4.2")
Traceback (most recent call last):
  File "<python-input-4>", line 1, in <module>
    int("4.2")
    ~~~^^^^^^^
ValueError: invalid literal for int() with base 10: '4.2'
>>> float("2,5")
Traceback (most recent call last):
  File "<python-input-5>", line 1, in <module>
    float("2,5")
    ~~~~~^^^^^^^
ValueError: could not convert string to float: '2,5'
>>> str(42) + "1"
'421'
>>> int(3.99)
3
>>> int(-3.99)
-3

int("4.2") fails because 4.2 is not an integer; int(float("4.2")) would work. float("2,5") fails because of the comma: Python expects the decimal point, in input as well, so keep this in mind if you are used to writing a decimal comma. For numbers from input, the typical pattern is therefore float(input("...")).

⁠In short: int, float and str convert explicitly; int cuts off the decimal places.

BackgroundWhy Python does not convert between text and numbers on its own

What should "2" + 3 give, the text '23' or the number 5? Some languages silently choose one of the two possibilities, JavaScript, for example, chooses '23'. Then a program calculates wrongly with numbers it has read in, without anyone noticing. Python follows the principle of not guessing in the face of ambiguity: it raises a TypeError and forces you to say what you mean with int, float or str. Between numeric types, on the other hand, Python does convert on its own (subsection 2.2), because there the meaning is unambiguous: $2+3.0$ is $5.0$.

Rounding: first by hand, then ready-made#

3 * 1.1 gives 3.3000000000000003, the price of three notebooks at €$1.10$ each, with a rounding residue. You want to round such a result to an integer or to a few digits, and not only in the display, but as a value that you continue calculating with.

By hand. int cuts off. If you add $0.5$ first, cutting off turns into rounding: $\textcolor{#1b7f4a}{2.7+0.5}\textcolor{#15633a}{=}\textcolor{#c2410c}{3.2}$ becomes 3, $\textcolor{#1b7f4a}{2.2+0.5}\textcolor{#15633a}{=}\textcolor{#c2410c}{2.7}$ becomes 2. This is the rule taught at school, “round up from 5”:

Terminal
>>> int(2.7 + 0.5)
3
>>> int(2.5 + 0.5)
3
>>> int(3.5 + 0.5)
4
>>> int(-2.7 + 0.5)
-2

The last line is wrong: $-2.7$ is closer to $-3$. Because int cuts off toward zero, the trick works only for positive numbers.

Ready-made. The built-in function round rounds correctly, including negative numbers.

Definition 10.5 (round)

round(x) returns the integer closest to $x$. If $x$ lies exactly halfway between two integers, round returns the even one of the two. round(x, n) rounds to $n$ decimal places and returns a float.

Terminal
>>> round(2.7)
3
>>> round(-2.7)
-3
>>> round(2.5)
2
>>> round(3.5)
4
>>> round(-2.5)
-2
>>> round(3.14159, 2)
3.14
>>> round(2.675, 2)
2.67
>>> f"{2.675:.20f}"
'2.67499999999999982236'

round(2.675, 2) gives $2.67$ and not $2.68$, and that is not an error: the stored value of 2.675 lies just below $2.675$, as the last line shows, so $2.67$ is the nearest number with two decimal places. If you want to round down or round up, use math.floor or math.ceil.

Comparison.

$x$int(x + 0.5)round(x)
$2.7$33
$2.5$32
$3.5$44
$-2.5$$-2$$-2$
$-2.7$$-2$$-3$

The two ways differ in two places: for exact halves such as $2.5$, where round goes to the even number, and for negative numbers, where the way by hand is wrong. The ready-made way is correct for all numbers and follows the same rule as the rounding of float values in subsection 4.6.

⁠In short: round rounds to the nearest number and, for exact halves, to the even one; int(x + 0.5) works only for positive numbers and always rounds halves up.

BackgroundWhy rounding goes to the even number

The rule from school rounds every exact half up. With many rounded values, this adds up to an error that always points in the same direction. An example: $\textcolor{#1b7f4a}{0.5+1.5+2.5+3.5}\textcolor{#15633a}{=}\textcolor{#c2410c}{8}$. Rounded by the school rule, the sum becomes $\textcolor{#1b7f4a}{1+2+3+4}\textcolor{#15633a}{=}\textcolor{#c2410c}{10}$. Rounded to the even number, it becomes $\textcolor{#1b7f4a}{0+2+2+4}\textcolor{#15633a}{=}\textcolor{#c2410c}{8}$: half of the cases go up, the other half down, and on average the errors cancel out. That is why IEEE 754, in its default setting, rounds every calculation with float to the even significand in a tie, and Python adopts the same rule for round. It also prevents a value that you repeatedly subtract and add back from slowly drifting in one direction.

Application: a running pace calculator#

With input, float and an f-string, you can write a small tool for runners: it asks for the distance and time of a run and outputs the pace in two forms, in kilometers per hour and in minutes per kilometer, the measure common in running. If you divide the minutes by the kilometers, the second measure comes out directly; for the first, you convert the minutes to hours beforehand.

tempo.pyPython
# Pace calculator: the pace of a run in two forms
strecke = float(input("Strecke in km: "))
zeit = float(input("Zeit in min: "))

km_pro_h = strecke / (zeit / 60)     # convert minutes to hours
min_pro_km = zeit / strecke          # min / km gives min per km

print(f"Tempo: {km_pro_h:.2f} km/h")
print(f"Zeit pro km: {min_pro_km:.2f} min")

When started, the script asks for the two values one after the other; here, 5.2 and 27 are typed in:

Windows (PowerShell)Terminal
PS> py tempo.py
Strecke in km: 5.2
Zeit in min: 27
Tempo: 11.56 km/h
Zeit pro km: 5.19 min
LinuxTerminal
$ python3 tempo.py
Strecke in km: 5.2
Zeit in min: 27
Tempo: 11.56 km/h
Zeit pro km: 5.19 min

If you type 5,2 with a decimal comma, the script aborts with the ValueError from subsection 10.4. Catching such inputs and asking again is a skill of its own that this chapter does not need.

⁠In short: float(input(...)) reads a number, and an f-string outputs the result with a suitable number of digits.

Exercises for Section 10#

Exercise 37 ★ Text and number

Predict and check: (a) "ab" * 3, (b) "Bus" + str(42), (c) len("Bahn") * 2, (d) int("7") + int("3"), (e) "7" + "3", (f) str(1 / 4).

Solution
Terminal
>>> "ab" * 3
'ababab'
>>> "Bus" + str(42)
'Bus42'
>>> len("Bahn") * 2
8
>>> int("7") + int("3")
10
>>> "7" + "3"
'73'
>>> str(1 / 4)
'0.25'

(b) str turns the number into text; only then does + work. (c) len returns 4, an int, and $\textcolor{#1b7f4a}{4\cdot2}\textcolor{#15633a}{=}\textcolor{#c2410c}{8}$ is a calculation, not a repetition. (d) and (e) show the difference: after the conversion into numbers, + calculates; with text, it concatenates.

Exercise 38 ★★ Formatting

For each line, write an f-string that produces exactly this text from the given variables.

  1. strecke = 4700 (in meters) $\to$ Strecke = 4.70 km

  2. menschen = 8.1e9 $\to$ Menschen auf der Erde: 8.10e+09

  3. anteil = 0.125 $\to$ Anteil: 12.5%

  4. c_feld = 1019 $\to$ 0x3fb and 01111111011

Solution
Terminal
>>> strecke = 4700
>>> f"Strecke = {strecke / 1000:.2f} km"
'Strecke = 4.70 km'
>>> menschen = 8.1e9
>>> f"Menschen auf der Erde: {menschen:.2e}"
'Menschen auf der Erde: 8.10e+09'
>>> anteil = 0.125
>>> f"Anteil: {anteil:.1%}"
'Anteil: 12.5%'
>>> c_feld = 1019
>>> f"{c_feld:#x}"
'0x3fb'
>>> f"{c_feld:011b}"
'01111111011'

(a) A whole expression may stand in the curly braces, here the conversion from meters to kilometers. (b) .2e writes the number in scientific notation with two decimal places. (c) The specifier % multiplies by 100 and appends the percent sign. (d) #x adds the prefix 0x; 011b pads with zeros to 11 digits, as in the exponent field of $0.1$ in Fig. 7.

Exercise 39 ★★ Rounding by hand and ready-made

Fill in the table for $\textcolor{#1b7f4a}{x}\textcolor{#15633a}{=}\textcolor{#c2410c}{0.5}$, $1.5$, $-0.5$, $-1.5$, $4.49$ with the columns int(x + 0.5), round(x), math.floor(x), int(x). Predict first, then check. For which values do all four columns give the same result?

Solution
Terminal
>>> import math
>>> int(0.5 + 0.5), round(0.5), math.floor(0.5), int(0.5)
(1, 0, 0, 0)
>>> int(1.5 + 0.5), round(1.5), math.floor(1.5), int(1.5)
(2, 2, 1, 1)
>>> int(-0.5 + 0.5), round(-0.5), math.floor(-0.5), int(-0.5)
(0, 0, -1, 0)
>>> int(-1.5 + 0.5), round(-1.5), math.floor(-1.5), int(-1.5)
(-1, -2, -2, -1)
>>> int(4.49 + 0.5), round(4.49), math.floor(4.49), int(4.49)
(4, 4, 4, 4)
$x$int(x + 0.5)round(x)math.floor(x)int(x)
$0.5$1000
$1.5$2211
$-0.5$00$-1$0
$-1.5$$-1$$-2$$-2$$-1$
$4.49$4444

Only for $4.49$ do all four agree: the number is positive, not an exact half, and its fractional part is smaller than $0.5$. For halves, round goes to the even number ($0.5\to0$, $1.5\to2$, $-1.5\to-2$). The method by hand, int after adding 0.5, always rounds halves up, that is, toward the larger number, and therefore turns $-1.5$ into $-1$. math.floor rounds down, int toward zero; the two differ only for negative numbers.

Exercise 40 ★★ A sound level calculator

Write a script pegel.py that asks for two sound pressures in pascals, a quiet one and a loud one, and outputs by what factor the loud one is larger (with two decimal places) and by how many decibels (with one decimal place), $20\log_{10}(p_\mathrm{loud}/p_\mathrm{quiet})$ as in Exercise 30. Test it with $0.02\,\mathrm{Pa}$ and $1.2\,\mathrm{Pa}$.

Solution
pegel.pyPython
# Sound level calculator: two sound pressures as factor and in dB
import math

p_leise = float(input("Leiser Schalldruck in Pa: "))
p_laut = float(input("Lauter Schalldruck in Pa: "))

faktor = p_laut / p_leise
pegel_db = 20 * math.log10(faktor)    # difference in dB

print(f"Faktor: {faktor:.2f}")
print(f"Unterschied: {pegel_db:.1f} dB")
Windows (PowerShell)Terminal
PS> py pegel.py
Leiser Schalldruck in Pa: 0.02
Lauter Schalldruck in Pa: 1.2
Faktor: 60.00
Unterschied: 35.6 dB

On Linux, python3 pegel.py gives the same. The result fits Exercise 30: factor 60, that is, $35.6\,\mathrm{dB}$.

Exercise 41 ★ An error when reading input

A script contains the lines strecke = input("Strecke in km: ") and print("Doppelte Strecke:", strecke * 2). For the input 5, it outputs 55. Explain this behavior and fix the error. What does your improved script output for the input 2.5?

Solution

input always returns a str (subsection 10.3). strecke * 2 therefore repeats the text '5' instead of calculating. The fix: convert the input with float.

einlesen.pyPython
# Read in a distance and double it, with type conversion
strecke = float(input("Strecke in km: "))
print("Doppelte Strecke:", strecke * 2)
LinuxTerminal
$ python3 einlesen.py
Strecke in km: 2.5
Doppelte Strecke: 5.0

With int instead of float, the input 2.5 would have failed with a ValueError; that is why float is the right choice for distances and other numbers with decimal places.
