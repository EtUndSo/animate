What this stage is about:

Computers store numbers as sequences of zeros and ones. This section explains the binary system, shows how to convert by hand and with Python, and clarifies which fractions can be written with finitely many digits in the binary system.

The positional numeral system#

To understand how a computer stores numbers, you first have to say precisely what a sequence of digits such as 4705 actually means. Then the same idea can be carried over to bases other than 10.

Thousands, hundreds, tens, ones. In 4705, the 4 stands for four thousands, the 7 for seven hundreds, the 0 for no tens and the 5 for five ones. Each position is worth ten times as much as the one to its right.

Definition 3.1 (Positional numeral system)

Let $B\ge2$ be a natural number, the base. In the positional numeral system with base $B$, a sequence of digits $z_{n-1}\ldots z_1z_0$ with $0\le z_i<B$ stands for the number

$$\textcolor{#1b7f4a}{z_{n-1}B^{n-1}+\dots+z_1B^1+z_0B^0}\textcolor{#15633a}{=}\textcolor{#c2410c}{\sum_{i=0}^{n-1}z_i\,B^i .}$$

The number $B^i$ is called the place value of position $i$. Positions are counted from the right, starting at $\textcolor{#1b7f4a}{i}\textcolor{#15633a}{=}\textcolor{#c2410c}{0}$.

Example

In the familiar decimal system, $\textcolor{#1b7f4a}{B}\textcolor{#15633a}{=}\textcolor{#c2410c}{10}$: $\textcolor{#1b7f4a}{4705}\textcolor{#15633a}{=}\textcolor{#c2410c}{4\cdot10^3+7\cdot10^2+0\cdot10^1+5\cdot10^0}\textcolor{#15633a}{=}\textcolor{#c2410c}{4000+700+0+5}$.

⁠In short: In a positional numeral system, each digit is multiplied by the place value of its position, and everything is added up.

The binary number#

A memory cell of the computer distinguishes only two states, like a light switch: on or off. For numbers, you therefore need a positional numeral system with only two digits.

Switches that double. Picture a row of switches. The rightmost one counts 1, the next 2, then 4, 8, 16: each counts twice as much as its right neighbor. The number is the sum of the values of all switches that are on.

Definition 3.2 (Binary number)

A binary number is a number in the positional numeral system with base $\textcolor{#1b7f4a}{B}\textcolor{#15633a}{=}\textcolor{#c2410c}{2}$. Its digits are 0 and 1.

A digit of a binary number is called a bit, short for binary digit. This chapter denotes the bits of a number by $b_i$, counted from the right starting at $\textcolor{#1b7f4a}{i}\textcolor{#15633a}{=}\textcolor{#c2410c}{0}$. So that a binary number is not confused with a decimal number, you write the base as a small number after it: $10011_2$. The value is

$$\textcolor{#1b7f4a}{b_{n-1}\ldots b_1b_0\,{}_2}\textcolor{#15633a}{=}\textcolor{#c2410c}{\sum_{i=0}^{n-1}b_i\,2^i .}$$

Example

$10011_2$ has the bits $\textcolor{#1b7f4a}{b_4}\textcolor{#15633a}{=}\textcolor{#c2410c}{1}$, $\textcolor{#1b7f4a}{b_3}\textcolor{#15633a}{=}\textcolor{#c2410c}{0}$, $\textcolor{#1b7f4a}{b_2}\textcolor{#15633a}{=}\textcolor{#c2410c}{0}$, $\textcolor{#1b7f4a}{b_1}\textcolor{#15633a}{=}\textcolor{#c2410c}{1}$, $\textcolor{#1b7f4a}{b_0}\textcolor{#15633a}{=}\textcolor{#c2410c}{1}$. The calculation is shown step by step in Fig. 3: the number is 19.

In Python, you write a binary number with the prefix 0b. The interactive mode displays it as a decimal number, because the object is an ordinary int:

Terminal
>>> 0b10011
19
>>> type(0b10011)
<class 'int'>

The method bit_length of an int tells how many bits the number needs without leading zeros:

Terminal
>>> (19).bit_length()
5

⁠In short: A binary number has only the digits 0 and 1, the bits; each bit counts $2^i$.

The byte#

A single bit can distinguish only two values. Memory and data transmission therefore work with groups of bits of a fixed size.

Definition 3.3 (Byte)

A byte is a group of 8 bits.

With $n$ bits, you can form $2^n$ different patterns, because each bit doubles the number of possibilities. A byte thus has $\textcolor{#1b7f4a}{2^8}\textcolor{#15633a}{=}\textcolor{#c2410c}{256}$ patterns and can represent the integers from 0 to 255. Memory sizes are counted in bytes: a 64-bit number occupies 8 bytes.

Example

The result is one less than the next place value $\textcolor{#1b7f4a}{2^8}\textcolor{#15633a}{=}\textcolor{#c2410c}{256}$. This holds for every number made of ones only: $n$ ones give $2^n-1$, just as $\textcolor{#1b7f4a}{999}\textcolor{#15633a}{=}\textcolor{#c2410c}{10^3-1}$ in the decimal system.

⁠In short: A byte is 8 bits; it can take 256 different values, the numbers 0 to 255.

Converting to binary: first by hand, then ready-made#

Fig. 3 converts from binary to decimal. For the opposite direction, there is a method that needs only floor division and remainder.

The idea. If you divide an integer $n\ge0$ by 2, the remainder is the last bit $b_0$: all other place values $2,4,8,\ldots$ are even; only $b_0\cdot1$ can contribute an odd part. The quotient $n\,/\!/\,2$ contains the remaining bits, moved one position to the right. If you divide it by 2 again, the remainder is $b_1$, and so on, until the quotient is 0.

By hand. The remainders, read from bottom to top, are the bits. In interactive mode, divmod does each step:

Terminal
>>> divmod(19, 2)
(9, 1)
>>> divmod(9, 2)
(4, 1)
>>> divmod(4, 2)
(2, 0)
>>> divmod(2, 2)
(1, 0)
>>> divmod(1, 2)
(0, 1)
$n$$n\,/\!/\,2$$n\,\%\,2$Bit
1991$b_0$
941$b_1$
420$b_2$
210$b_3$
101$b_4$

Read from the bottom: $\textcolor{#1b7f4a}{b_4b_3b_2b_1b_0}\textcolor{#15633a}{=}\textcolor{#c2410c}{10011}$, so $\textcolor{#1b7f4a}{19}\textcolor{#15633a}{=}\textcolor{#c2410c}{10011_2}$.

Ready-made. Python comes with the conversion. The function bin returns the binary representation as a string with the prefix 0b; the function format with the specifier "b" returns it without the prefix, and with "08b" padded to eight digits with leading zeros. For the way back, the function int takes a string and the base:

Terminal
>>> bin(19)
'0b10011'
>>> format(19, "b")
'10011'
>>> format(19, "08b")
'00010011'
>>> int("10011", 2)
19
>>> bin(-19)
'-0b10011'

Python writes negative numbers with a minus sign before the prefix, just as you also write them in the decimal system.

Comparison. By hand and ready-made, the same bits appear: $10011$. The ready-made way is shorter and makes no reading errors when reversing the remainders; you need the way by hand to understand why the remainders are the bits.

⁠In short: Repeated division by 2 yields the bits as remainders, the last bit first; ready-made, bin and format do the job.

The hexadecimal number#

Bit sequences quickly become long and hard to read: nobody reads out $0011111111111011$ without errors. You need a shorter notation from which you can still read off the bits immediately.

Four bits are one digit. Four bits have $\textcolor{#1b7f4a}{2^4}\textcolor{#15633a}{=}\textcolor{#c2410c}{16}$ patterns. If you give each of these 16 patterns a character of its own, you can split any bit sequence into groups of four and replace each group by one character.

Definition 3.4 (Hexadecimal number)

A hexadecimal number is a number in the positional numeral system with base $\textcolor{#1b7f4a}{B}\textcolor{#15633a}{=}\textcolor{#c2410c}{16}$. The digits are 0 to 9 and a to f for the values 10 to 15.

Because $\textcolor{#1b7f4a}{16}\textcolor{#15633a}{=}\textcolor{#c2410c}{2^4}$, each hexadecimal digit stands for exactly four bits:

01234567
89abcdef
10001001101010111100110111101111

So a byte is exactly two hexadecimal digits.

Example

$\textcolor{#1b7f4a}{255}\textcolor{#15633a}{=}\textcolor{#c2410c}{1111\,1111_2}$ is $\mathtt{ff}_{16}$ in hexadecimal, because $\textcolor{#1b7f4a}{15\cdot16+15}\textcolor{#15633a}{=}\textcolor{#c2410c}{255}$. You split the long bit sequence from the beginning of this subsection into groups of four, starting from the right: $\textcolor{#1b7f4a}{0011\;1111\;1111\;1011_2}\textcolor{#15633a}{=}\textcolor{#c2410c}{\mathtt{3ffb}_{16}}$. In Python, you write hexadecimal numbers with the prefix 0x; hex converts, and int with the base 16 converts back:

Terminal
>>> 0xff
255
>>> hex(255)
'0xff'
>>> int("3ffb", 16)
16379
>>> bin(0x3ffb)
'0b11111111111011'

In the output of bin, the two leading zeros of the first group of four are missing; Python leaves out leading zeros.

⁠In short: Hexadecimal is base 16; each digit stands for four bits, a byte for two digits.

Binary fractions#

Prices, weights and temperatures have decimal places. A computer must be able to write them with zeros and ones, too.

Digits to the right of the point. In the decimal system, the digits to the right of the decimal point mean tenths, hundredths, thousandths. In the binary system, the place value halves from position to position: halves, quarters, eighths, sixteenths.

Definition 3.5 (Binary fraction)

A binary fraction is a number in the binary system with digits to the right of the point, the binary point. Position $k$ to the right of the point has the place value $2^{-k}$:

$$\textcolor{#1b7f4a}{0.b_{-1}b_{-2}\ldots b_{-m}\,{}_2}\textcolor{#15633a}{=}\textcolor{#c2410c}{\sum_{k=1}^{m}b_{-k}\,2^{-k} .}$$

Example

$\textcolor{#1b7f4a}{0.101_2}\textcolor{#15633a}{=}\textcolor{#c2410c}{1\cdot\tfrac12+0\cdot\tfrac14+1\cdot\tfrac18}\textcolor{#15633a}{=}\textcolor{#c2410c}{\tfrac58}\textcolor{#15633a}{=}\textcolor{#c2410c}{0.625}$ and $\textcolor{#1b7f4a}{0.011_2}\textcolor{#15633a}{=}\textcolor{#c2410c}{\tfrac14+\tfrac18}\textcolor{#15633a}{=}\textcolor{#c2410c}{\tfrac38}\textcolor{#15633a}{=}\textcolor{#c2410c}{0.375}$.

Not every fraction can be written as a finite binary fraction. In the decimal system, this is familiar: $\textcolor{#1b7f4a}{\frac14}\textcolor{#15633a}{=}\textcolor{#c2410c}{0.25}$ terminates, $\textcolor{#1b7f4a}{\frac13}\textcolor{#15633a}{=}\textcolor{#c2410c}{0.333\ldots}$ does not. The following theorem says which numbers terminate in the binary system.

Theorem 3.6 (Finite binary fractions)

A number $x$ can be written as a binary fraction with finitely many digits exactly when there is an integer $p\ge0$ such that $x\cdot2^p$ is an integer.

Proof: Shifting the point

In the binary system, multiplying by $2^p$ shifts the point $p$ positions to the right, just as multiplying by $10^p$ does in the decimal system.

If $x$ has at most $p$ digits to the right of the point, then after the shift no digit is left to the right of the point, and $x\cdot2^p$ is an integer.

Conversely, if $\textcolor{#1b7f4a}{x\cdot2^p}\textcolor{#15633a}{=}\textcolor{#c2410c}{n}$ is an integer, $n$ has a finite binary representation. Shifting the point in it $p$ positions to the left gives $\textcolor{#1b7f4a}{x}\textcolor{#15633a}{=}\textcolor{#c2410c}{n\cdot2^{-p}}$ with at most $p$ digits to the right of the point.

Applying it to $\frac38$ and $\frac1{10}$. $\textcolor{#1b7f4a}{\frac38\cdot2^3}\textcolor{#15633a}{=}\textcolor{#c2410c}{3}$ is an integer, so the binary fraction terminates, namely after three digits. For $\frac1{10}$, we get $\textcolor{#1b7f4a}{\frac1{10}\cdot2^p}\textcolor{#15633a}{=}\textcolor{#c2410c}{\frac{2^{p}}{10}}\textcolor{#15633a}{=}\textcolor{#c2410c}{\frac{2^{p-1}}{5}}$. But a power of two is never divisible by 5, because its only prime factors are twos. For no $p$ is this an integer: in the binary system, $0.1$ has infinitely many digits. The same holds for every fraction in lowest terms whose denominator contains a prime factor other than 2, for example $\textcolor{#1b7f4a}{0.2}\textcolor{#15633a}{=}\textcolor{#c2410c}{\frac15}$ and $\textcolor{#1b7f4a}{0.3}\textcolor{#15633a}{=}\textcolor{#c2410c}{\frac3{10}}$.

⁠In short: A binary fraction terminates exactly when the denominator in lowest terms is a power of two; $0.1$ does not terminate.

The doubling method#

What do the infinitely many binary digits of $0.1$ look like? For the digits to the right of the point, there is a method that corresponds to dividing by 2 for integers.

The idea. If you multiply a binary fraction $0.b_{-1}b_{-2}b_{-3}\ldots{}_2$ by 2, the point moves one position to the right: the result is $b_{-1}.b_{-2}b_{-3}\ldots{}_2$. In front of the point there is now the first digit $b_{-1}$, that is, 0 or 1, and behind it the rest. You repeat this with the rest.

Definition 3.7 (Doubling method)

For $0\le x<1$, the doubling method determines the binary digits of $x$: you double $x$. The integer part of the result, 0 or 1, is the next digit; you continue with the part to the right of the point. The method ends when this part is 0.

Example 1$0.625$

$\textcolor{#1b7f4a}{2\cdot0.625}\textcolor{#15633a}{=}\textcolor{#c2410c}{1.25}$, digit 1, continue with $0.25$. $\textcolor{#1b7f4a}{2\cdot0.25}\textcolor{#15633a}{=}\textcolor{#c2410c}{0.5}$, digit 0. $\textcolor{#1b7f4a}{2\cdot0.5}\textcolor{#15633a}{=}\textcolor{#c2410c}{1.0}$, digit 1, rest 0, done: $\textcolor{#1b7f4a}{0.625}\textcolor{#15633a}{=}\textcolor{#c2410c}{0.101_2}$, as in the previous subsection.

Example 2$0.1$

To keep rounding from creeping in, you calculate with the fraction $\frac{z}{10}$ and double only the integer numerator $z$. If $2z\ge10$, the digit is 1 and you subtract 10; otherwise, the digit is 0:

$$\textcolor{#1b7f4a}{0.1}\textcolor{#15633a}{=}\textcolor{#c2410c}{0.0\,0011\,0011\,0011\ldots{}_2 .}$$

How close you get to $0.1$ with the first digits is shown by the sum of the place values. The ones come in pairs: at positions 4 and 5, then 8 and 9, then 12 and 13, and so on. A pair at positions $4k$ and $4k+1$ is worth $\textcolor{#1b7f4a}{2^{-4k}+2^{-(4k+1)}}\textcolor{#15633a}{=}\textcolor{#c2410c}{3\cdot2^{-(4k+1)}}$. The first four pairs, that is, the first 17 digits, give (Fig. 5)

The sum comes ever closer to $0.1$ but does not reach it with any finite number of digits. The error after the 17 digits is $\textcolor{#1b7f4a}{0.1-\frac{13107}{131072}}\textcolor{#15633a}{=}\textcolor{#c2410c}{\frac{1}{655360}}\textcolor{#15633a}{=}\textcolor{#c2410c}{0.1\cdot2^{-16}}$: after digit 17, the same pattern as in $0.1$ itself follows again, only moved 16 positions to the right.

⁠In short: Doubling moves the next binary digit in front of the point; for $0.1$, this gives the infinite sequence $0.0\,0011\,0011\ldots{}_2$.

BackgroundWhy the digits have to repeat

In the method for $0.1$, each step leaves a fraction $\frac{z}{10}$ with a numerator $z$ from 0 to 9. So there are only ten possible states. After ten steps at the latest, one of them must occur for the second time, and because each step depends only on the current fraction, everything repeats from there on. The same argument shows that every fraction $\frac{z}{q}$ in every positional numeral system either terminates or becomes periodic, with a period of fewer than $q$ digits. In the decimal system, you know this from $\textcolor{#1b7f4a}{\frac17}\textcolor{#15633a}{=}\textcolor{#c2410c}{0.\overline{142857}}$.

Exercise 10 ★★ Finite or not?

Use Theorem 3.6 to decide which numbers have a finite binary fraction, and give it where it exists: $0.75$, $0.2$, $0.375$, $\frac13$, $0.05$, $12.5$.

Solution

According to Theorem 3.6, what matters is whether the denominator in lowest terms is a power of two:

  • $\textcolor{#1b7f4a}{0.75}\textcolor{#15633a}{=}\textcolor{#c2410c}{\frac34}$, denominator $\textcolor{#1b7f4a}{4}\textcolor{#15633a}{=}\textcolor{#c2410c}{2^2}$: finite, $0.11_2$.

  • $\textcolor{#1b7f4a}{0.2}\textcolor{#15633a}{=}\textcolor{#c2410c}{\frac15}$: denominator 5, not finite.

  • $\textcolor{#1b7f4a}{0.375}\textcolor{#15633a}{=}\textcolor{#c2410c}{\frac38}$, denominator $2^3$: finite, $0.011_2$.

  • $\frac13$: denominator 3, not finite.

  • $\textcolor{#1b7f4a}{0.05}\textcolor{#15633a}{=}\textcolor{#c2410c}{\frac1{20}}$, denominator $\textcolor{#1b7f4a}{20}\textcolor{#15633a}{=}\textcolor{#c2410c}{4\cdot5}$ contains 5: not finite.

  • $\textcolor{#1b7f4a}{12.5}\textcolor{#15633a}{=}\textcolor{#c2410c}{\frac{25}2}$: finite, $\textcolor{#1b7f4a}{12.5}\textcolor{#15633a}{=}\textcolor{#c2410c}{8+4+\frac12}\textcolor{#15633a}{=}\textcolor{#c2410c}{1100.1_2}$.

Exercise 11 ★★ How finely does a kitchen scale weigh?

A digital kitchen scale stores each weight as a 12-bit integer. The range from 0 to $5\,\mathrm{kg}$ is divided into steps of equal width, one step for each bit pattern.

  1. How many steps are there, and what is the largest number the scale stores?

  2. How wide is one step in grams? Calculate with Python.

  3. Is the step width in kilograms a finite binary fraction? Justify your answer with Theorem 3.6.

Solution

(a) 12 bits have $\textcolor{#1b7f4a}{2^{12}}\textcolor{#15633a}{=}\textcolor{#c2410c}{4096}$ patterns, so there are 4096 steps. The largest number is $\textcolor{#1b7f4a}{4095}\textcolor{#15633a}{=}\textcolor{#c2410c}{2^{12}-1}$, twelve ones.

(b)

Terminal

>>> 5 / 4096 * 1000

(c) $\textcolor{#1b7f4a}{\frac5{4096}\cdot2^{12}}\textcolor{#15633a}{=}\textcolor{#c2410c}{5}$ is an integer, so the step width is a finite binary fraction: $\textcolor{#1b7f4a}{\frac{5}{4096}}\textcolor{#15633a}{=}\textcolor{#c2410c}{101_2\cdot2^{-12}}\textcolor{#15633a}{=}\textcolor{#c2410c}{0.000000000101_2}$. That is also why Python shows no rounding digits: the result is exact, because $\textcolor{#1b7f4a}{1.220703125}\textcolor{#15633a}{=}\textcolor{#c2410c}{\frac{625}{512}}$, too, has a denominator that is a power of two.

The first twelve digits: $\textcolor{#1b7f4a}{0.3}\textcolor{#15633a}{=}\textcolor{#c2410c}{0.010011001100\ldots{}_2}$. In step 7, $\frac2{10}$ appears again, as in step 3; from there on, everything repeats. So the period begins at step 3 and has length 4: $0.01\,0011\,0011\ldots{}_2$. It is the same period $0011$ as for $0.1$, only at a different position, because $\textcolor{#1b7f4a}{0.3}\textcolor{#15633a}{=}\textcolor{#c2410c}{0.2+0.1}$ and both have the sequence of numerators $2,4,8,6$.

The positional numeral system
Definition 3.1 (Positional numeral system)

Let $B\ge2$ be a natural number, the base. In the positional numeral system with base $B$, a sequence of digits $z_{n-1}\ldots z_1z_0$ with $0\le z_i<B$ stands for the number

$$\textcolor{#1b7f4a}{z_{n-1}B^{n-1}+\dots+z_1B^1+z_0B^0}\textcolor{#15633a}{=}\textcolor{#c2410c}{\sum_{i=0}^{n-1}z_i\,B^i .}$$

The number $B^i$ is called the place value of position $i$. Positions are counted from the right, starting at $\textcolor{#1b7f4a}{i}\textcolor{#15633a}{=}\textcolor{#c2410c}{0}$.

The binary number
Definition 3.2 (Binary number)

A binary number is a number in the positional numeral system with base $\textcolor{#1b7f4a}{B}\textcolor{#15633a}{=}\textcolor{#c2410c}{2}$. Its digits are 0 and 1.

The hexadecimal number
Definition 3.4 (Hexadecimal number)

A hexadecimal number is a number in the positional numeral system with base $\textcolor{#1b7f4a}{B}\textcolor{#15633a}{=}\textcolor{#c2410c}{16}$. The digits are 0 to 9 and a to f for the values 10 to 15.

Binary fractions
Definition 3.5 (Binary fraction)

A binary fraction is a number in the binary system with digits to the right of the point, the binary point. Position $k$ to the right of the point has the place value $2^{-k}$:

$$\textcolor{#1b7f4a}{0.b_{-1}b_{-2}\ldots b_{-m}\,{}_2}\textcolor{#15633a}{=}\textcolor{#c2410c}{\sum_{k=1}^{m}b_{-k}\,2^{-k} .}$$

Theorem 3.6 (Finite binary fractions)

A number $x$ can be written as a binary fraction with finitely many digits exactly when there is an integer $p\ge0$ such that $x\cdot2^p$ is an integer.

The doubling method
Definition 3.7 (Doubling method)

For $0\le x<1$, the doubling method determines the binary digits of $x$: you double $x$. The integer part of the result, 0 or 1, is the next digit; you continue with the part to the right of the point. The method ends when this part is 0.

Key relationships
  • On “The positional numeral system”: In a positional numeral system, each digit is multiplied by the place value of its position, and everything is added up.
  • On “The binary number”: A binary number has only the digits 0 and 1, the bits; each bit counts $2^i$.
  • On “The byte”: A byte is 8 bits; it can take 256 different values, the numbers 0 to 255.
  • On “Converting to binary: first by hand, then ready-made”: Repeated division by 2 yields the bits as remainders, the last bit first; ready-made, bin and format do the job.
  • On “The hexadecimal number”: Hexadecimal is base 16; each digit stands for four bits, a byte for two digits.
