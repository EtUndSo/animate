Chapter 1: A Linux to Practice On: WSL, Virtual Machine, Live USB Stick

Key points so far

Operating system, kernel and distribution

Terms
  • operating system – The operating system is the software that manages a computer's hardware, makes it available to the other programs through uniform services and keeps the programs apart from one another.
  • application program – A program that runs under an operating system and performs a task for the user is called an application program, or program for short.
  • kernel mode – In kernel mode, the running program may execute any instruction of the processor.
  • user mode – In user mode, certain instructions are blocked, such as direct access to devices and setting which program may use which part of main memory.
  • privileged instruction – Such a blocked instruction is called a privileged instruction.
  • kernel – The kernel (the core of the system) is the part of the operating system that runs in kernel mode.
  • drivers – The drivers also belong to the kernel: pieces of software that can control a particular device, such as a particular network card or a particular SSD.
  • system call – A system call is a request from a program to the kernel to perform a particular service, for example to open a file, read data or provide memory.
  • Linux
  • distribution – A distribution is a complete operating system that a vendor or a community assembles from the Linux kernel, tools, application programs and default settings and maintains as a whole.
  • package manager – Every distribution comes with a package manager: a program with which you install, update and remove software from the distribution's sources.
  • LTS release – Every two years in April, an LTS release (Long Term Support) appears, for which Canonical supplies security fixes and bug fixes for five years.
  • point release – A number like 26.04.1 denotes a point release: the same system with the fixes collected up to that point and new installation media.
Key relationships
  • The operating system manages the hardware, offers services to the programs and keeps them apart from one another.
  • The processor itself ensures that ordinary programs cannot touch the hardware directly.
  • The kernel is the only part of the system that is allowed to control the hardware directly.
  • Programs get hardware services only by asking the kernel for them through a system call.
  • Strictly speaking, Linux is only the kernel of an operating system.
  • Linux is the kernel; a distribution turns it into a complete system.
  • For a practice system, you choose the current LTS release, because it receives fixes for five years.

Three ways to a Linux of your own

Terms
  • terminal – A terminal is a program with a window into which you type commands as text and in which the computer's responses appear as text.
  • prompt – When it is ready, it shows a prompt at the beginning of the line.
Key relationships
  • WSL 2 is the fastest way, the virtual machine is the lab and the live USB stick is real Linux on real hardware.
  • For programming and the command line, you choose WSL 2, for labs a virtual machine and for real Linux on real hardware the live USB stick.
  • The terminal is the window in which you talk to the system in text form; at the end of each way, you open one.

Virtual machines: the computer within the computer

Terms
  • virtual machine – A virtual machine (VM) is a computer simulated by software, with its own processor, main memory, storage devices and network card.
  • host – The host is the real computer with the operating system under which the virtual machine runs.
  • guest – The guest is the operating system that runs in the virtual machine.
  • hypervisor – A hypervisor is the software that creates and runs virtual machines.
  • Hardware virtualization
  • snapshot – A snapshot is a saved state of a virtual machine to which you can return at any time.
  • address – Like a router at home. Every device in a network has a number under which others reach it, its address.
  • NAT mode – In NAT mode (Network Address Translation), the hypervisor works like a router for the VM.
Key relationships
  • A virtual machine is a computer made of software in which a whole operating system runs.
  • The host is the real computer, the guest is the system in the VM.
  • The hypervisor builds the virtual machines and watches over them.
  • With hardware virtualization, a guest kernel runs directly on the processor, but everything that would affect the real machine ends up with the hypervisor.
  • A snapshot freezes the state of a VM, and restoring it discards everything that came afterward.
  • In NAT mode, the VM gets out onto the network, but nobody gets in from outside.

WSL 2: Linux alongside Windows

Terms
  • Windows Subsystem for Linux – The Windows Subsystem for Linux, version 2 (WSL 2), is a component of Windows that starts a real Linux kernel in a small virtual machine, which Windows itself creates, starts and stops.
Key relationships
  • WSL 2 is a real Linux in a small VM that Windows manages itself.
  • wsl --install -d Ubuntu-26.04 in an administrator PowerShell, restart, create a user.
  • wsl -l -v shows which distributions are set up and whether they run under WSL 2.
  • In the WSL terminal, cat /etc/os-release shows the distribution and uname -r shows Microsoft's kernel.
  • Linux in WSL finds drive C: under /mnt/c.
  • Windows sees the Linux files in File Explorer under “Linux”; the address is \\wsl.localhost\Ubuntu-26.04.
  • Files that you work with in Linux belong in the Linux part, not in /mnt/c.
  • WSL 2 is ideal for the command line and programming; for network labs and your own devices, it is too far removed from the hardware.

Storage device, image and checksum

Terms
  • image – An image is a file that contains the contents of an entire storage device sector by sector, with partition table, file systems and boot files.
  • ISO image – An ISO image is an image in the format of a CD or DVD; it has the extension .iso.
  • checksum – A checksum is a short value that a fixed method calculates from the contents of a file.
  • SHA-256 – The images of Linux distributions use the SHA-256 method, which is specified by the U.S.
  • integrity – So the checksum proves the integrity of the file with respect to the list, not its origin.
  • digital signature
Key relationships
  • An image is an entire storage device in a single file.
  • The checksum is the fingerprint of a file: same contents, same value; any change, a different value.
  • Compare checksums completely, preferably with sha256sum -c or with Get-FileHash and -eq.
  • A matching checksum proves that the file is unchanged, but not that it is genuine.

How a PC starts

Terms
  • firmware – The firmware is a program that is stored permanently in a memory chip on the main circuit board (the motherboard) and runs first when the computer is switched on.
  • UEFI – Today's PCs use firmware following the UEFI standard (Unified Extensible Firmware Interface); its predecessor was called BIOS, and many people still call the firmware “BIOS” today.
  • EFI system partition – A UEFI firmware reads its boot programs from a small, dedicated partition with a FAT file system, the EFI system partition; it is the first of the four partitions from the example in subsection 5.2.
  • boot order – The boot order is the list of boot entries in the order in which the firmware tries them at power-on.
  • boot menu – The boot menu is a selection that the firmware displays when you press a key at power-on; in it, you choose an entry once, without changing the boot order.
  • boot loader – A boot loader is the boot program that the firmware loads and that in turn loads the kernel of the operating system into main memory and starts it.
  • GRUB – Linux distributions usually use the GRUB boot loader.
  • Secure Boot
  • BitLocker – BitLocker is the drive encryption of Windows; in Windows Home, it is called device encryption.
  • recovery key – If the boot chain has been changed, Windows demands the recovery key, a 48-digit number that was generated when the encryption was switched on.
Key relationships
  • The firmware runs first after switching on and loads a boot program from the EFI system partition.
  • For a one-time start from the stick, you use the boot menu and leave the boot order as it is.
  • The firmware loads the boot loader, and the boot loader loads the kernel.
  • Secure Boot starts only boot programs with a valid seal; it checks authenticity and encrypts nothing.
  • Before you do anything to the boot chain, you back up the 48-digit recovery key.

A virtual machine with VirtualBox

Key relationships
  • Install VirtualBox from https://www.virtualbox.org, without the Extension Pack.
  • If hardware virtualization is off, you switch on only this one setting in the firmware, with the recovery key backed up.
  • A new VM with the checked image, without unattended installation, with 6 GB of memory, 2 processors and a 25 GB disk.
  • In the VM, you install Ubuntu quite normally, because everything the installer erases is the virtual hard disk.
  • After the installation, create a snapshot “sauber”; you can return to it at any time, but you lose everything that came later.
  • Ctrl+Alt+T opens the terminal in Ubuntu; there, uname -r shows Ubuntu's kernel.

The live system

Terms
  • live system – A live system is an operating system that starts and runs entirely from a removable storage device without mounting the computer's built-in storage devices.
  • squashfs – … squashfs is a file system that stores its entire contents compressed in a single file and can only be read, not written to.
  • tmpfs – … tmpfs is a file system whose files are in main memory.
  • overlay – An overlay places two file systems on top of each other and shows them as one: a lower, read-only layer and an upper, writable layer.
  • persistence – For a live system, persistence means that it stores changes not in main memory but in an additional storage area on the stick, so that they survive the restart.
Key relationships
  • A live system runs from the stick and from main memory and leaves the internal SSD alone.
  • squashfs is a compressed file system that can only be read.
  • tmpfs is a file system in main memory, writable and volatile.
  • The overlay shows a read-only and a writable layer as one tree; all changes end up at the top.
  • After switching off, everything you changed in the live system is gone, and every start is fresh again.
  • Persistence turns the stick into a system that remembers, but in Ubuntu, it is a poorly maintained add-on.

The live USB stick: preparing, writing, starting

Terms
  • Fast Startup
  • writing tool – A writing tool is a program that writes an image sector by sector onto an entire storage device.
Key relationships
  • If you write to the right storage device and do not change the boot chain, you take hardly any risk with the live stick.
  • Unplug other storage and recognize the stick by “Removable” and its size; only then write.
  • Go to the stick via “Restart”, not via “Shut down”, and do not touch the Windows partitions in the live system.
  • Download the image and SHA256SUMS from Ubuntu, compare the checksum and continue only if the answer is True.
  • A writing tool such as balenaEtcher or Rufus turns the stick into a copy of the image; everything that was on it before is gone.
  • “Restart”, boot menu, the “UEFI” entry with the stick, “Try Ubuntu”, never “Install”.
  • In the live system, lsblk shows the internal SSD without a mount point, that is, unused.
  • Switch off, unplug the stick, and Windows starts as before; convert the stick back with the same care as when writing.

Chapter 2: The Shell: First Commands

Key points so far

Terminal and shell

Terms
  • terminal emulator – A terminal emulator is a program that shows a window with lines of text, passes each keystroke as a character to another program and displays in the window each character that this program sends back.
  • shell – A shell is a program that accepts commands as text, runs them or has other programs run them, and then waits for the next command.
  • bash – On Ubuntu, Debian and Fedora, the terminal opens the shell bash, short for “Bourne-Again Shell”.
  • prompt – The prompt is the text that the shell writes at the start of a line when it is ready to read the next command.
  • current folder – The shell always works in a particular folder. This folder is called the current folder.
  • root – The end character. Every Linux system has a user account that may do anything: read anyone else's files, change system files, install programs. This account is called root.
  • session – A session is the time from the start of a shell in a terminal until its end.
Key relationships
  • The terminal emulator is only the window: it passes on keystrokes and draws characters without understanding them.
  • The shell is the program that reads your commands and has them run; on Ubuntu, it is bash.
  • The prompt shows the user, the computer and the current folder; $ means ordinary user, # means root.
  • Each terminal window has its own shell and thus its own session, which ends with exit.

The structure of a command line

Terms
  • command line – A command line is everything you type after the prompt before you press Enter.
  • words – The shell splits it at spaces into words; several spaces in a row separate like a single one.
  • command – The first word of a command line is the command: the name of what is to be run.
  • argument – Every word of the command line after the command is an argument.
  • option – An option is an argument that begins with a minus sign and determines how the command works.
  • short option – A short option consists of a minus sign and a single letter, such as -r.
  • long option – A long option begins with two minus signs followed by a whole word, such as --kernel-release.
  • option with a value – An option with a value requires an additional piece of information, such as a number.
Key relationships
  • The shell splits every command line into words at the spaces.
  • The first word of the line is the command, and in its name every letter counts, including whether it is upper or lower case.
  • The words after the command are its arguments; the shell passes them on in order, and the command decides what they mean.
  • Options begin with a minus sign and set how a command works; short options can be bundled.
  • Long options begin with two minus signs and a whole word; they are longer but self-explanatory.
  • Some options require a value, which comes as the next word, is attached directly or follows an equals sign.
  • After --, every word is an ordinary argument, even if it begins with a minus sign.

Kinds of commands

Terms
  • program file – A program file is a file that contains an executable program.
  • search path – The search path is the list of folders in which the shell looks for a program file with the name of the command; it starts the first one it finds.
  • builtin command – A builtin command is a command that the shell runs itself, without starting another program.
  • alias – An alias is a name that the shell replaces with a stored text while reading a command line if the name stands at the start as a command.
Key relationships
  • Most commands are program files, files with an executable program in them.
  • The shell looks for program files in the folders of the search path, one after another, and starts the first one that matches.
  • The shell handles builtin commands itself; commands such as cd and exit, which change the shell itself, have to be built in.
  • An alias is a shortcut that the shell replaces with a longer command before the search.
  • type says what the shell does with a name; which only finds program files in the search path.

Finding help

Terms
  • short help – The short help is a brief description that a program outputs when you call it with the option --help.
  • help – The builtin command help shows the instructions for the shell's builtin commands.
  • manual page – A manual page, or man page for short, is the detailed description of a command, a file format, a system call or another part of the system, collected in the manual that every Linux comes with.
  • man – The command man with the name as an argument displays it.
  • pager – A pager is a program that shows a long text one screen at a time and lets you scroll and search in it.
  • sections – The manual is divided into numbered sections, one for each kind of content (Table 3).
  • apropos – The command apropos searches the names and short descriptions of all manual pages for a keyword and lists the hits with their section.
Key relationships
  • command --help shows a program's options at a glance.
  • For builtin commands, you ask the shell: help name.
  • man name shows the complete instructions in a fixed layout; you read the usage under SYNOPSIS with the help of the characters [ ], | and ....
  • man shows its pages in the pager less: the Space bar pages forward, / searches, q quits.
  • The manual has numbered sections; if a name occurs more than once, man 5 passwd selects the page from section 5.
  • apropos keyword finds manual pages whose short description contains the keyword.
  • Name unknown: apropos; builtin: help; program file: --help for the overview, man for everything.

Working faster: completion, history, keyboard shortcuts

Terms
  • Completion – Completion finishes a partly typed word as soon as you press the Tab key.
  • history – The history is the numbered list of recently typed command lines that the shell keeps in its memory.
  • reverse search – The reverse search searches the history from the newest line to the oldest for the text you type; you start it with Ctrl+R.
  • Ctrl+C – The key combination Ctrl+C asks the program that is currently running in the terminal to stop immediately; almost all programs then stop, and the shell shows the prompt again.
  • Ctrl+D – The key combination Ctrl+D at the start of a line tells the program that is currently reading that no more input follows.
  • keyboard shortcut – A keyboard shortcut of the command line is a key combination that the shell does not write into the line as a character but carries out as an instruction to edit the line or the window.
Key relationships
  • The Tab key completes command and file names; pressed twice, it shows all the possibilities.
  • The shell remembers every line in the history; the Up arrow key and history bring it back.
  • Ctrl+R searches backward in the history for what you type; Enter runs the hit.
  • Ctrl+C interrupts the running program or discards the partly typed line.
  • Ctrl+D tells the reading program “no more input”; on the empty command line, it ends the shell.
  • Ctrl+A and Ctrl+E jump to the start and the end, Ctrl+U, Ctrl+K and Ctrl+W delete parts of the line, Ctrl+L clears the window.

Exploring the system

Key relationships
  • uname -a names the kernel, the computer and the processor; the first line of /etc/os-release names the distribution.
  • whoami gives your name, id your user ID and your groups.
  • date gives the date and time, uptime the uptime and the load of the last 1, 5 and 15 minutes.
  • free -h shows the main memory; the column that matters is available, not free.
  • df -h / shows the size, used space and free space of the file system; -h calculates in multiples of 1024, -H in multiples of 1000.

Two implementations of the core commands: GNU and uutils

Terms
  • coreutils – The coreutils (“core utilities”) are a collection of over a hundred basic commands for files, text and system information, including ls, cat, head, cp, uname, date and df.
  • uutils coreutils – … uutils coreutils, uutils for short, is a rewrite of the coreutils in the programming language Rust that is meant to behave like the GNU implementation.
  • prefix gnu – Ubuntu 26.04 also installs the GNU implementation of the coreutils, under names with the prefix gnu: gnuls is GNU's ls, gnuuname its uname, gnudate its date and so on.
Key relationships
  • The coreutils are the collection of core commands; the classic implementation comes from the GNU project.
  • Ubuntu 26.04 uses uutils, a rewrite in Rust, for most core commands; --version shows which implementation answers.
  • In Ubuntu 26.04, you reach the GNU implementation of each core command with the prefix gnu, for example gnuls.
  • uutils and GNU deliver the same results but word help texts and error messages differently.

Chapter 3: Files, Directories and Paths

Key points so far

Files, directories and the directory tree

Terms
  • file – A file is a sequence of bytes that is stored permanently under a name.
  • directory – A directory is a list of entries.
  • directory tree – The directories of a Linux system form a single directory tree: every directory except one is entered under its name in exactly one other directory.
  • root directory – The one directory that is not entered in any other is called the root directory; it is written as a single slash /.
  • parent directory – The directory in which another one is entered is called its parent directory.
  • subdirectory – Conversely, every directory that is entered in another one is a subdirectory of it.
Key relationships
  • A file is a stored sequence of bytes with a name; what the bytes mean is decided by the program that reads them.
  • A directory is a list that links names to files or to further directories.
  • All directories hang in a single tree with the root /; further storage devices are mounted instead of getting a letter.

The working directory and paths

Terms
  • working directory – The working directory of a running program is the directory in which it is currently working.
  • path – A path is a sequence of names, separated by slashes /, that describes the route through the directory tree to a file or a directory.
  • absolute path – An absolute path begins with /.
  • relative path – A relative path does not begin with /.
  • home directory – A user's home directory is the directory that belongs to them for their own files.
  • tilde – The abbreviation for it is the tilde ~: if it is at the beginning of a word, the shell replaces it with the path of your home directory before it starts the command.
  • cd – The builtin command cd (short for “change directory”) makes the directory that its argument denotes the shell's new working directory.
Key relationships
  • The working directory is the location in the tree to which commands without a location refer; pwd names it.
  • A path is a set of directions through the tree: names, separated by slashes.
  • An absolute path begins with / and is valid from everywhere.
  • A relative path begins without / and is valid from the working directory.
  • . is the directory itself, .. the parent directory; in the root, .. leads back to the root.
  • The home directory is your own place in the tree; ~ at the beginning of a word stands for its path.
  • cd changes the working directory: cd path goes there, cd goes home, cd - goes back, cd .. goes one level up.

Showing the contents of a directory

Terms
  • ls – The command ls prints, for each directory given as an argument, the names of its entries, sorted by name, and for every other file its name.
  • hidden file – A hidden file is a file or directory whose name begins with a dot.
  • -F
  • -l
  • regular file – A - stands for a regular file, that is, a file with contents such as a text or a program; a d stands for a directory.
  • -h – Together with -l, the option -h (short for “human-readable”) makes ls print each size in the largest suitable unit: K for 1024 bytes, M for $1024^2$ bytes, G for $1024^3$ bytes.
Key relationships
  • ls lists the entries of directories; for a regular file, it gives its name.
  • A name with a dot at the start makes a file invisible to the ordinary ls; ls -a shows everything.
  • ls -F marks directories with / and programs with *.
  • ls -l shows the type, permissions, owner, group, size, modification time and name of each entry; -d shows the directory itself instead of its contents.
  • ls -lh writes sizes with K, M, G of 1024 each and rounds up.
  • -S sorts by size, -t by time, -r reverses, -R descends into all subdirectories.
  • File names may contain anything except / and distinguish between uppercase and lowercase; spaces and a dash at the start cause trouble, so you avoid them.

Viewing files

Terms
  • cat – The command cat reads the files given as arguments in turn and writes out their bytes unchanged, one after the other.
  • less – If less receives a file as an argument, it shows the file's contents page by page.
  • head, tail – The command head writes out the first lines of a file, the command tail the last ones.
  • wc
  • file – The command file examines each file named and describes what it contains, such as text, an image in a particular format, a program or a directory.
Key relationships
  • cat writes out the contents of files one after the other; for short files, this is the quickest look inside.
  • less file shows a file page by page, with paging and search, without changing it.
  • head shows the beginning, tail the end of a file, ten lines each or as many as -n says.
  • wc counts lines, words and bytes; -l, -w, -c select one of the numbers.
  • file determines the type of a file from its contents, regardless of name and extension.

Creating files and directories

Terms
  • mkdir – The command mkdir (short for “make directory”) creates a new, empty directory for each argument.
  • -p – The option -p (short for “parents”) also creates missing intermediate directories and reports no error if a directory already exists.
  • touch – The command touch sets the time of the last modification and of the last access of each file named to the current time.
  • text editor – A text editor is a program with which you create and change text files; it stores only the characters, no font and no formatting.
  • nano – … nano is a simple text editor that runs in the terminal and constantly shows the most important shortcuts at the bottom edge.
  • tree
Key relationships
  • mkdir creates directories; with -p, it also creates all missing levels above them.
  • touch creates an empty file or, for an existing one, only sets the modification time to now.
  • nano file opens a text editor in the terminal; Ctrl+O saves, Ctrl+X quits.
  • tree shows a subtree with all its levels at once.

Copying, moving, deleting

Terms
  • cp – The command cp (short for “copy”) copies a file: cp source target creates a new file with the same contents under the name target.
  • -r – With the option -r (short for “recursive”), cp copies a directory together with everything in it, level by level.
  • mv – The command mv (short for “move”) gives a file or a directory a new name or a new location: mv source target renames source to target.
  • rm – The command rm (short for “remove”) removes the named files from their directories, immediately and usually without asking.
  • rmdir – The command rmdir (short for “remove directory”) removes a directory only if it is empty.
  • pattern – A pattern is a word of the command line that contains one of the characters *, ? or [.
Key relationships
  • cp source target creates an independent copy and overwrites an existing target without asking; -i asks first.
  • cp -r copies whole directories; if the target already exists, the copy is created inside it.
  • mv renames or moves, depending on whether the target is an existing directory; an existing target is replaced without asking.
  • rm deletes files immediately and permanently; rm -i asks first.
  • rmdir deletes only empty directories, rm -r whole subtrees without asking.
  • Patterns with *, ? and […] select many names at once; the shell replaces them with the matching names before the command starts.

The directory structure of Linux

Terms
  • Filesystem Hierarchy Standard – The Filesystem Hierarchy Standard, FHS for short, specifies which directories a Linux system should have and which kind of files belongs in which of them.
  • /usr – The directory /usr contains the programs, libraries and unchanging data that come with the distribution.
  • library – A library is a file with program parts that many programs share instead of each containing them itself.
  • /etc – The directory /etc contains the configuration that applies to the whole system.
  • /home – The directory /home contains a home directory for each ordinary user, named after that user.
  • /root – The home directory of root is kept apart from it in /root.
  • /var – The directory /var (short for “variable”) contains data that change while the system is running.
  • log files – An important part of it is /var/log with the log files: files to whose end a program continuously writes what happens, each entry with the date and time.
  • /tmp – The directory /tmp is intended for temporary files.
  • device file – A device file is an entry in the directory tree behind which there are no stored contents but a device that a driver in the kernel manages.
  • virtual file system – A virtual file system is a file system whose files are not on any storage device; the kernel creates their contents at the moment a program reads them.
Key relationships
  • The FHS specifies which directory is there for what; that is why all Linux systems look alike in their basic outline.
  • Under /usr is everything that the distribution brings along in programs and fixed data; your own add-on software belongs in /usr/local or /opt.
  • /etc is the place for the configuration of the whole system, in the form of text files.
  • The users live in /home/<name>, root lives in /root.
  • /var takes in everything that changes during operation; the logs are in /var/log.
  • /tmp is a shared place for short-lived files; what is to stay belongs in the home directory.
  • In /dev, devices appear as files; you read and write them with the same tools as regular files.
  • /proc and /sys are windows into the kernel: their files are created when they are read and reveal the uptime, the processor, the devices and the running programs.

Inodes and links

Terms
  • inode – An inode is the administrative record of a file in the file system.
  • hard link – A hard link is a further directory entry for an existing inode, that is, an additional name for the same file.
  • link count – The inode keeps count of how many entries point to it; this number is called the link count.
  • symbolic link – A symbolic link is a file of its own of type l whose only contents are a path.
  • usr-merge – The usr-merge, the merging of /usr, is the arrangement common today in which the directories /bin, /sbin and /lib are symbolic links to usr/bin, usr/sbin and usr/lib.
Key relationships
  • The inode is the administrative record of a file with all the information except the name; ls -i shows its number, stat its contents.
  • A directory is a table of names and inode numbers; a file name is only an entry that points to an inode.
  • A hard link is a second name for the same inode; the link count in the second column of ls -l counts the names.
  • rm removes a name; the file disappears only with its last name.
  • A symbolic link is a small file with a path in it; it redirects accesses and can point nowhere if the target is missing.
  • /bin, /sbin and /lib are symbolic links to /usr today; old paths keep working.
  • A hard link is a name with equal rights for the same inode, only in the same file system and only for files; a symbolic link is a signpost that may point anywhere, even nowhere.

Storage devices and mounting

Terms
  • lsblk
  • findmnt – The command findmnt lists the mounted file systems with mount point (TARGET), source (SOURCE), type (FSTYPE) and options (OPTIONS).
  • df – If df receives paths as arguments, it shows for each path the file system in which it is located, with size, used and free space.
  • /mnt/c – Under WSL 2, the Windows drive C: is mounted at /mnt/c, as a file system of type 9p.
Key relationships
  • lsblk shows storage devices and partitions with size and mount point.
  • findmnt shows which file system is mounted at which directory; findmnt -T path answers the question for a single path.
  • df -hT path shows the type, size and free space of the file system in which a path is located.
  • Under WSL 2, /mnt/c is a file system of its own with the rules of Windows; for Linux work, everything belongs in the home directory.

Finding files and measuring space

Terms
  • find – The command find walks through the subtree below each given starting directory, entry by entry and level by level.
  • -name pattern – The test -name pattern passes if the name of an entry, that is, the last part of its path, matches the pattern; the pattern follows the same rules as in subsection 6.6.
  • -type type – The test -type type passes if an entry is of the given type: f for a regular file, d for a directory, l for a symbolic link, b and c for device files.
  • -size n – The test -size n compares the size of an entry with n; +n means greater than n, -n less than n, and n alone exactly n.
  • -mtime n – The test -mtime n compares the age of the last modification in whole days of 24 hours with n; partial days are dropped, and +n and -n mean more and less, as with -size.
  • ! – A ! in front of a test negates it.
  • -maxdepth n – The option -maxdepth n directly after the starting directories limits the search to n levels below the starting directory.
  • action – What find does with a match is determined by an action; if none is given, it is -print, which prints the path.
  • du – The command du (short for “disk usage”) adds up, for each given directory and each subdirectory in it, the space that the files occupy on the storage device, in units of 1024 bytes.
Key relationships
  • find start tests walks through a subtree and prints the paths of the entries that pass all tests.
  • -name "pattern" searches by name; the quotes make sure that find, not the shell, applies the pattern.
  • -type f, -type d and -type l select regular files, directories or symbolic links.
  • -size +n and -size -n search by size; because find rounds up to whole units, you use bytes (c) for exact limits.
  • -mtime and -mmin search by age in whole days or minutes, -newer by comparison with another file.
  • Tests in a row must all pass, ! negates one, -maxdepth limits the depth; use -delete only after a trial run without it.
  • du -sh shows how much space a directory occupies; whole blocks are counted, which is why even a tiny file occupies 4 KiB.

Chapter 4: Streams, Redirection, Pipes and Exit Status

Key points so far

Processes and their three streams

Terms
  • process
  • process ID – The kernel keeps each process separate from all others. It gives each process a number, the process ID.
  • stream – A stream is a sequence of bytes that a process reads or writes in order.
  • end of the stream – If nothing more arrives during reading and nothing more can arrive, the end of the stream has been reached; the kernel tells the reading process by having a read request return zero bytes.
  • Standard input – Standard input (stdin for short) is the stream from which a process reads when it is not told otherwise.
  • Standard output – Standard output (stdout for short) is the stream to which a process writes its results.
  • Standard error – Standard error (stderr for short) is a second output stream to which a process writes error messages, warnings and notices.
  • file descriptor – A file descriptor, descriptor for short, is a small integer under which the kernel keeps track of an open file for a process.
Key relationships
  • A program is a file; a process is a running execution of it, with its own memory, its own open files, its own working directory and its own number.
  • A stream is a sequence of bytes that a process reads or writes in order without knowing where they come from; when a read request returns zero bytes, the stream has ended.
  • Standard input is the way in to a process; in the terminal it is the keyboard, and Ctrl+D ends the stream.
  • Standard output is the way out for the results of a process; in the terminal it ends up on the screen.
  • Standard error is a separate way out for messages; in the terminal it mixes with standard output.
  • A descriptor is the number by which a process refers to an open file when dealing with the kernel; 0, 1 and 2 are the three standard streams.

Redirecting output

Terms
  • redirection – A redirection is an instruction to the shell to connect a descriptor of the new process to a different file before the program starts.
  • appending – The notation command >> file connects standard output to the file for appending: every byte written goes after the existing contents, and nothing is deleted.
  • copy – The notation n>&m makes descriptor $n$ a copy of descriptor $m$: afterward, $n$ leads to the same open file as $m$ at that moment.
Key relationships
  • command > file sends standard output into a file that the shell creates or empties beforehand; the program notices nothing of this.
  • >> appends standard output to a file without touching the old contents.
  • 2> redirects standard error; a number in front of > selects the descriptor.
  • /dev/null swallows everything that is written to it; 2> /dev/null hides messages.
  • 2>&1 makes the error output lead to where standard output currently leads; &> is the short form for both ways out into one file.
  • Redirections take effect from left to right; 2>&1 copies the target that 1 has at that moment, which is why it goes after > file.
  • Never read from a file and write with > into the same file; the shell empties it before the program can read it.

Redirecting input

Terms
  • here document – A here document is a redirection of the form command <<ENDMARKER, followed by lines of text and finally a line that contains only the end marker.
  • here string – A here string is a redirection of the form command <<< "text".
Key relationships
  • command < file makes a file the standard input; the program reads a stream and does not know the name.
  • A here document gives a command the following lines, up to the end marker, as standard input.
  • A here string gives a command one line of text as standard input, with a line end appended.

Pipes and filters

Terms
  • pipe – A pipe connects the standard output of one process to the standard input of another.
  • filter – A filter is a program that reads data from its standard input, transforms it and writes the result to its standard output.
  • pipeline – A pipeline is a sequence of commands connected by |.
  • tee – The command tee reads its standard input and writes everything it reads both to its standard output and to every file named as an argument.
  • Unix philosophy – The Unix philosophy is a principle for building programs.
Key relationships
  • command1 | command2 connects the standard output of the first program to the standard input of the second; both run at the same time, and the messages still go to the screen.
  • A filter reads its standard input, transforms it and writes the result to its standard output; that is why it fits behind a pipe.
  • A pipeline lines up filters like the stations of an assembly line; each station works with what the previous one delivers.
  • tee file passes its input on unchanged and at the same time writes a copy into the file.
  • Small programs that do one thing well and read and write text can be connected into ever new tool chains.

The exit status

Terms
  • exit status – When it ends, every process leaves behind an integer from 0 to 255, its exit status.
Key relationships
  • Every process ends with a number from 0 to 255; 0 means success, and $? returns the number of the most recently ended command.
  • The nonzero number says which failure it was; what it means is stated in the program's manual page.
  • 127 means “not found”, 126 “not executable”, and $128 + n$ means “ended by interrupt message $n$”, such as 130 after Ctrl+C.

Chaining commands

Terms
  • AND list – The notation command1 && command2 is an AND list: the shell runs command2 only if command1 ended with exit status 0. The exit status of the AND list is that of the last command executed.
  • OR list – The notation command1 || command2 is an OR list: the shell runs command2 only if command1 ended with a nonzero exit status.
Key relationships
  • The semicolon runs commands one after another without paying attention to whether they succeed.
  • command1 && command2 runs the second command only if the first one succeeded.
  • command1 || command2 runs the second command only if the first one failed.
  • a && b || c is an “if, then, else” only if b cannot fail; otherwise c also runs after a failed b.
  • A pipeline has the exit status of its last command; PIPESTATUS shows all of them, and pipefail makes earlier errors count as well.

Turning output into arguments

Terms
  • xargs – The command xargs reads its standard input and splits it into words at spaces, tabs and line ends.
  • argument list limit – The kernel limits how many bytes all the arguments of a program start may have together; getconf ARG_MAX shows this argument list limit.
Key relationships
  • What comes through a pipe is input, not an argument; programs without input do not see it, and filters take it for data.
  • xargs command turns the words of its standard input into arguments for the command.
  • There is an upper limit for the arguments of a program start; xargs distributes the words over several calls on its own, and with -n in batches of a fixed size.
  • With find -print0 and xargs -0, the null byte separates the names, and spaces remain part of the name.
  • find … -exec command {} + passes the matches directly as arguments to a command, names with spaces included; with \; instead of +, one at a time.

Chapter 5: How the Shell Reads a Command Line: Expansion, Quoting, Variables, Environment

Key points so far

Expansion: patterns, braces and the tilde

Terms
  • Expansion – Expansion is the step in which the shell replaces certain parts of the words of a command line with other text.
  • Pathname expansion – Pathname expansion is the expansion that replaces a pattern with the names of the existing files and directories that it matches; each match becomes a word of its own.
  • Brace expansion – Brace expansion turns a word with curly braces into several words.
  • Tilde expansion – Tilde expansion replaces a tilde at the beginning of a word.
Key relationships
  • During expansion, the shell rewrites parts of the command line before the program starts; the program sees only the result.
  • Pathname expansion replaces a pattern with the sorted names that match it, in paths as well; no pattern character stands for a slash.
  • A pattern captures hidden files only if it itself has a dot at this position; . and .. are never among the matches.
  • With no match, a pattern stays as it was typed, and the program receives it literally.
  • Brace expansion creates several words from a list or sequence in curly braces, in the written order and without looking at files.
  • Tilde expansion replaces a tilde at the beginning of a word with a home directory, your own or that of the named user.

Variables, command substitution and arithmetic expansion

Terms
  • shell variable – A shell variable is a name under which the running shell stores a text, the value of the variable.
  • assignment – You create a variable or change its value with an assignment of the form NAME=value; there is no space before or after the equals sign.
  • Parameter expansion – Parameter expansion replaces $NAME or ${NAME} with the value of the variable.
  • parameter – In general, anything that stores a value which the shell inserts with a preceding dollar sign is called a parameter.
  • Command substitution – Command substitution $(command) executes the command in the parentheses in a separate process and replaces itself with that command's standard output.
  • Arithmetic expansion – Arithmetic expansion $((expression)) computes the expression in the double parentheses with integers and inserts the result as text.
Key relationships
  • A shell variable stores a text under a name; NAME=value without spaces stores it.
  • $NAME inserts the value of a variable, ${NAME} marks off the name; an unknown variable yields empty text.
  • $(command) inserts the output of a command into the command line, without the line ends at the end.
  • $((…)) calculates with integers and inserts the result; / drops the remainder, % returns it.

Word splitting and quoting

Terms
  • printf – The builtin command printf writes text according to a format, its first argument.
  • Word splitting – Word splitting splits the results of parameter expansion, command substitution and arithmetic expansion into separate words, provided these expansions were not within double quotes.
  • Quoting – Quoting means marking characters of a command line so that the shell takes them literally instead of giving them a special meaning.
  • backslash – A backslash \ outside of quotes removes the special meaning of the character directly after it.
Key relationships
  • printf "[%s]\n" writes each argument in brackets on a line of its own and thus makes visible which arguments a command receives.
  • Word splitting splits the results of expansions without double quotes at spaces, tabs and line ends; after that, pattern characters in them take effect as well.
  • Quoting marks characters that the shell is to take literally; there are single and double quotes and the backslash.
  • Between single quotes, everything is literal; only a single quote itself is not possible there.
  • Between double quotes, the shell inserts values with $ but does not split them, and it does not evaluate patterns, tildes or braces.
  • The backslash protects exactly one character; at the end of a line, it continues the command line on the next line.
  • At the end, the shell removes the typed quotes and backslashes and joins the pieces of a word; quotes from values remain ordinary characters.
  • Expansions belong in double quotes, text for programs in single quotes; otherwise a value can turn into several arguments.
  • Splitting, braces, then tilde, parameters, arithmetic expansion and command substitution from left to right, then word splitting, patterns and finally quote removal.

Environment and inheritance

Terms
  • child process – If a process starts another one, the new process is a child process of the first.
  • parent process – The starting process is called its parent process.
  • environment – The environment of a process is a list of texts of the form NAME=value that the process receives when it starts, in addition to its arguments.
  • environment variable – An environment variable is a shell variable that is marked for passing on; the shell writes all marked variables into the environment of every child process.
  • export – The builtin command export marks a variable: export NAME marks an existing one, export NAME=value assigns and marks in one step.
  • env – The command env starts a command with a modified environment.
Key relationships
  • A process that another process starts is its child process; it does not automatically receive the shell's variables.
  • The environment is a list of entries NAME=value that every process receives when it starts; printenv shows it.
  • export marks a shell variable as an environment variable; every child receives it in its environment.
  • A child inherits a copy of the environment; it can change the copy but cannot pass anything back.
  • NAME=value command gives only this command a setting of its own; the shell stays unchanged.
  • printenv shows the environment, env starts a command with a modified or empty environment.

How the shell finds programs: PATH

Terms
  • PATH – The environment variable PATH contains the search path as text: the directories, separated by colons, in the order in which the shell searches them.
Key relationships
  • PATH is the search path as text, the directories separated by colons and in the order of the search.
  • Without a slash, the shell searches in PATH and takes the first match; with a slash, it starts exactly the named file.
  • The working directory is not part of the search path; you start a program there with ./.
  • PATH="directory:$PATH" puts a directory of your own at the front of the search path; at the front means priority, and the old value must be kept.

Startup files and aliases

Terms
  • startup file – A startup file is a text file with commands for the shell that the shell reads and runs when it starts, as if you had typed the lines.
  • source – The builtin command source file reads the file and runs its lines in the running shell, as if you had typed them.
  • login shell – A login shell is a shell that starts at a login, for example after a user name and password on a text console, for a connection from another computer or when you open the WSL terminal.
  • alias – The builtin command alias name='text' defines an alias: if name is the first word of a command, the shell replaces it with text.
Key relationships
  • A startup file contains commands that the shell runs every time it starts; a new interactive bash reads ~/.bashrc.
  • source file runs a file in the running shell; its settings remain because no child process comes into being.
  • A login shell reads /etc/profile and ~/.profile, which on Ubuntu reads in ~/.bashrc; an interactive shell without a login reads only ~/.bashrc.
  • Permanent settings belong in ~/.bashrc, your own programs in ~/.local/bin; source ~/.bashrc makes changes take effect immediately.
  • alias name='text' defines an abbreviation for the running interactive shell; it becomes permanent in ~/.bashrc.

Chapter 6: Text Tools and Regular Expressions

Key points so far

Text data: records, fields and line ends

Terms
  • record – A record is a line of a text file that contains the values of one table row.
  • fields – Its individual values are called fields; they stand one after the other in a fixed order.
  • separator – Between any two fields there is an agreed character, the separator.
  • column – The fields with the same number in all records together form a column.
  • CSV file – A CSV file is a text file in which each line is a record and the comma separates the fields.
  • header line – Often the first line contains the names of the columns instead of values; it is called the header line.
  • carriage return – The carriage return is an invisible character with the value 13, often written \r in programs.
Key relationships
  • A line with the values of a table row is a record; its values are the fields, separated by a separator and counted from the left.
  • A CSV file is a table as text with one record per line and commas between the fields; the first line often names the columns.
  • Windows ends lines with a carriage return and a newline; under Linux, the invisible carriage return becomes the last character of every line, and cat -A shows it as ^M.
  • tail -n +K starts at line $K$, head -n -K stops $K$ lines before the end; tail -n +2 removes a header line.
  • tail -f shows the end of a file and then everything that is appended, until Ctrl+C.

Cutting out columns and replacing characters: cut, tr and paste

Terms
  • cut – The command cut writes out only selected parts of each line of its input.
  • tr – The command tr reads its standard input character by character and writes it out changed.
  • paste – The command paste reads several files at the same time and writes the first line of each file side by side in one line, then the second lines and so on.
Key relationships
  • cut -d, -f2 cuts the second comma-separated field out of each line; -c cuts by character positions.
  • tr replaces characters according to two sets, deletes them with -d or squeezes repetitions with -s; tr -d '\r' removes Windows line ends.
  • paste puts lines of several files side by side, paste -s puts all lines of a file into one line, with -d setting the separator.

Sorting and counting: sort and uniq

Terms
  • sort – The command sort reads all lines of its input and writes them out in order.
  • sort key – -k A,B makes the fields from number $A$ to number $B$ the sort key: sort compares only this piece of the line.
  • locale – The locale, the language setting, is a set of rules for a language and a country.
  • uniq – The command uniq compares each line of its input with the line directly before it and, of several identical lines in a row, writes out only one.
Key relationships
  • sort compares lines character by character from the left according to the order of the characters; that is why 10 comes before 9.
  • sort -n compares the number at the beginning of the line by its value; lines without a number count as 0.
  • sort -t, -k3,3n sorts whole lines by the value of field 3; further -k decide in the case of a tie.
  • The locale determines how sort orders; C and C.UTF-8 order by character numbers, and LC_ALL=C sort makes a result the same on every computer.
  • uniq combines identical lines that stand directly one below the other; -c counts them, -d and -u select repeated or single ones.
  • sort | uniq -c | sort -rn counts how often each value occurs and puts the most frequent one at the top; sort -u delivers only the different values.

Numbering, sequences of numbers and differences: nl, seq and diff

Terms
  • nl – The command nl writes out each line of its input with a running number in front of it, separated by a tab.
  • seq – The command seq writes a sequence of numbers, one per line.
  • diff – The command diff compares two text files line by line and outputs what you would have to change in the first one to get the second one.
Key relationships
  • nl puts line numbers in front of the lines; it counts empty lines only with -ba.
  • seq start step end writes a sequence of numbers, also with decimal numbers and with limits from variables.
  • diff a b uses a, c and d to show which lines you would have to add, change or delete in a to get b; the exit status tells whether there are differences.

Searching with grep

Terms
  • grep – After the options, the command grep receives a search text as its first argument and then files.
Key relationships
  • grep searchtext file writes the lines that contain the search text; the exit status tells whether there were any.
  • -i ignores case, -v gives the other lines, -c their count, -n adds line numbers.
  • grep -o writes only the matching pieces, one per line; with wc -l, you thus count matches instead of lines.
  • With several files, grep names the origin of each line; -r searches whole directory trees, -l names only the file names.

Regular expressions: characters, classes and anchors

Terms
  • string – A string here is simply a sequence of characters, such as a word, a number or a whole line.
  • regular expression – A regular expression is a text that describes a set of strings.
  • match – A line matches a regular expression if a contiguous piece of it belongs to this set; this piece is called the match.
  • dot – The dot . in a regular expression matches any single character.
  • bracket expression – A bracket expression is a list of characters in square brackets; it matches exactly one character that is in the list.
  • character class – A character class is a named group of characters that you write inside a bracket expression as [:name:].
  • anchor – An anchor matches not a character but a position in the line.
Key relationships
  • A regular expression describes a set of strings; a line matches if a piece of it belongs to the set, and on the command line the expression stands in single quotes.
  • A dot matches any single character.
  • \ before a special character makes it ordinary; grep -F takes the whole search text literally.
  • […] matches exactly one character from the list, [^…] exactly one that is not in it; a-z in the list is a range.
  • [[:digit:]], [[:alpha:]] and their relatives select characters by kind; the locale determines what belongs to them.
  • ^ anchors an expression at the start of the line, $ at the end of the line; both match positions, not characters.

Regular expressions: repetitions, groups and alternatives

Terms
  • star – A star * after an ordinary character, a dot or a bracket expression matches any number of repetitions of it in a row, including none at all.
  • basic form – The basic form of regular expressions is the notation that grep uses without an option; it is called “basic regular expressions”, BRE for short.
  • extended form – In the extended form, called “extended regular expressions”, ERE for short, they are special characters as well; grep -E turns it on.
  • quantifier – A quantifier stands after an element of an expression and determines how often the element may occur in a row.
  • group – Parentheses combine part of an expression into a group; a quantifier after the group acts on it as a whole.
  • alternative – The vertical bar forms an alternative: a|b matches where a matches or where b matches.
Key relationships
  • x* means “any number of x, including none”; .* matches any sequence of characters.
  • grep -E turns on the extended form, in which + ? { } ( ) | are special characters; without -E, they are ordinary characters.
  • + at least once, ? at most once, {n,m} between $n$ and $m$ times; plus the star for any number of times.
  • (…) turns a part into one unit for quantifiers, a|b offers a choice; the bar binds most weakly.
  • In the basic form, { } and ( ) get a backslash in front, and \+ \? \| are an extra of the GNU tools there; when in doubt, write -E.
  • The match that begins furthest to the left wins, and from there the longest one; you can limit it with a negated bracket expression.
  • A regular expression checks the form of a string, not its meaning; 2026-13-45 has the form of a date.
  • The shell evaluates patterns against file names, the program evaluates regular expressions against lines; *, ? and the dot mean different things in the two.

Transforming in the stream: sed

Terms
  • sed – The command sed, short for “stream editor”, reads its input line by line.
  • line address
  • backreference – In the replacement text of s, a backreference \1 to \9 inserts the piece of the first to the ninth group; the opening parentheses are counted from the left.
Key relationships
  • sed applies its commands to every line of a stream and writes out the result without changing the file.
  • s/expression/replacement/ replaces the first match per line, with g all of them; & is the match itself.
  • A line address such as 3, $, /expression/ or 2,4 limits a command to certain lines; -n with p outputs only these.
  • d drops the selected lines from the stream; 1d removes the header line.
  • Groups remember their matches, and \1 to \9 insert them again in the replacement text in any order.
  • sed -i writes the result into a new file that replaces the old one; -i.bak keeps the old version. A redirection into the same file, by contrast, empties it.

Calculating with columns: awk

Terms
  • awk – The command awk runs a small program that is in its first argument after the options.
  • rules – The program consists of rules of the form condition {action}.
  • associative array – An associative array is a variable in awk that stores any number of values, each under a key of its own: s["Anna"] is the value under the key Anna.
Key relationships
  • An awk program consists of rules condition {action}, which awk applies to every line.
  • $1 to $NF are the fields of a line, $0 the whole line, NF their number; -F, splits at commas.
  • NR is the line number; conditions compare fields with numbers or text and are combined with &&, || and !.
  • awk variables collect values over all lines and start at 0; END outputs the result after the last line, printf formats it.
  • An associative array stores values under keys such as $2; this is how awk collects sums and counters per group in a single pass.

An analysis from start to finish

Key relationships
  • For every part of a question, there is a suitable small tool; awk is the most versatile, but not always the simplest.
  • A pipeline grows stage by stage, every intermediate result is checked, and whatever is needed more than once goes into a file.
  • Six small tools in a pipeline answer a question for which you would otherwise write a whole program.
