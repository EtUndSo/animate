Chapter 1: A Linux to Practice On: WSL, Virtual Machine, Live USB Stick

Operating system, kernel and distribution

The operating system
Definition 1.1 (Operating system)

The operating system is the software that manages a computer's hardware, makes it available to the other programs through uniform services and keeps the programs apart from one another.

Two operating modes of the processor
Definition 1.2 (Kernel mode and user mode)

A processor has at least two operating modes. In kernel mode, the running program may execute any instruction of the processor. In user mode, certain instructions are blocked, such as direct access to devices and setting which program may use which part of main memory. Such a blocked instruction is called a privileged instruction. If a program in user mode attempts a privileged instruction, the processor does not execute it: it interrupts the program and hands control to the operating system.

The kernel
Definition 1.3 (Kernel)

The kernel (the core of the system) is the part of the operating system that runs in kernel mode. It controls the hardware directly, divides the processor and main memory among the programs, manages the files and checks for every access whether it is allowed. All other programs run in user mode.

The system call
Definition 1.4 (System call)

A system call is a request from a program to the kernel to perform a particular service, for example to open a file, read data or provide memory. The program puts the number of the service and the necessary details in place and executes a special processor instruction. This instruction switches to kernel mode and jumps to a location in the kernel that the kernel itself set when the computer started. The kernel checks the request, handles it, switches back to user mode and gives the program the result.

Linux
Definition 1.5 (Linux)

Linux is a kernel. Linus Torvalds began it in 1991 as a student in Helsinki; today it is maintained by thousands of developers, at companies, at universities and in their spare time. Its source code is freely available under the GNU General Public License (GPL), version 2. In the strict sense, “Linux” refers only to this kernel; in everyday language, people often mean the whole system built on it.

The distribution
Definition 1.6 (Distribution)

A distribution is a complete operating system that a vendor or a community assembles from the Linux kernel, tools, application programs and default settings and maintains as a whole. Every distribution comes with a package manager: a program with which you install, update and remove software from the distribution's sources. Chapter 9 explains how it works.

Releases and long-term support
Definition 1.7 (Ubuntu release, LTS)

An Ubuntu release is named after the year and month in which it appeared: 26.04 appeared in April 2026. In addition, each release has a code name; 26.04 is called “Resolute Raccoon”. Every two years in April, an LTS release (Long Term Support) appears, for which Canonical supplies security fixes and bug fixes for five years. In between, interim releases appear, which are supported for only nine months. A number like 26.04.1 denotes a point release: the same system with the fixes collected up to that point and new installation media.

Three ways to a Linux of your own

The terminal
Definition 2.1 (Terminal)

A terminal is a program with a window into which you type commands as text and in which the computer's responses appear as text. When it is ready, it shows a prompt at the beginning of the line.

Virtual machines: the computer within the computer

The virtual machine
Definition 3.1 (Virtual machine)

A virtual machine (VM) is a computer simulated by software, with its own processor, main memory, storage devices and network card. It runs a complete operating system with its own kernel, which behaves as if it were running on real hardware.

Host and guest
Definition 3.2 (Host, guest)

The host is the real computer with the operating system under which the virtual machine runs. The guest is the operating system that runs in the virtual machine.

The hypervisor
Definition 3.3 (Hypervisor)

A hypervisor is the software that creates and runs virtual machines. It allots them processor time, main memory and storage devices, simulates their devices and separates them from one another and from the host.

Hardware virtualization
Definition 3.4 (Hardware virtualization)

Hardware virtualization is an extension of the processor with which a hypervisor lets guest systems run directly on the processor and itself gets control as soon as a guest wants to do something that would affect the real machine. At Intel it is called VT-x (Virtualization Technology), at AMD it is called AMD-V. All of today's PC processors have it; on some computers, however, it is switched off at the factory and must be switched on in the computer's basic settings.

The snapshot
Definition 3.5 (Snapshot)

A snapshot is a saved state of a virtual machine to which you can return at any time. It comprises the settings of the VM and the contents of all its virtual hard disks; if you take it while the VM is running, it also contains the contents of its main memory.

The virtual network: NAT
Definition 3.6 (NAT mode)

In NAT mode (Network Address Translation), the hypervisor works like a router for the VM. The VM has an address of its own in a private network that exists only between it and the hypervisor. The hypervisor forwards the VM's connections under the host's address and passes the replies back to the VM. Connections that start from outside do not reach the VM as long as you do not set up forwarding.

WSL 2: Linux alongside Windows

The Windows Subsystem for Linux
Definition 4.1 (WSL 2)

The Windows Subsystem for Linux, version 2 (WSL 2), is a component of Windows that starts a real Linux kernel in a small virtual machine, which Windows itself creates, starts and stops. One or more distributions run in this VM, each kept apart from the others. Microsoft builds the Linux kernel from the official Linux source code and delivers it with updates; the distribution comes from its vendor, in the case of Ubuntu from Canonical.

Storage device, image and checksum

The image
Definition 5.4 (Image, ISO image)

An image is a file that contains the contents of an entire storage device sector by sector, with partition table, file systems and boot files. An ISO image is an image in the format of a CD or DVD; it has the extension .iso.

The checksum
Definition 5.5 (Checksum, SHA-256)

A checksum is a short value that a fixed method calculates from the contents of a file. The images of Linux distributions use the SHA-256 method, which is specified by the U.S. standard FIPS 180-4. From every file, no matter how large, it yields a value of 256 bits, written as 64 hexadecimal digits 0–9 and a–f. The same contents always result in the same value. SHA-256 is built so that every change, even that of a single bit, results in a completely different value and that, as far as is known today, nobody can deliberately produce a second file with the same value.

How a PC starts

The firmware
Definition 6.1 (Firmware, UEFI)

The firmware is a program that is stored permanently in a memory chip on the main circuit board (the motherboard) and runs first when the computer is switched on. It checks and starts the hardware and then loads a boot program from a storage device. Today's PCs use firmware following the UEFI standard (Unified Extensible Firmware Interface); its predecessor was called BIOS, and many people still call the firmware “BIOS” today.

Boot order and boot menu
Definition 6.2 (Boot order, boot menu)

The boot order is the list of boot entries in the order in which the firmware tries them at power-on. The boot menu is a selection that the firmware displays when you press a key at power-on; in it, you choose an entry once, without changing the boot order.

The boot loader
Definition 6.3 (Boot loader)

A boot loader is the boot program that the firmware loads and that in turn loads the kernel of the operating system into main memory and starts it. In doing so, it can display a menu in which you choose between several systems or startup variants.

Secure Boot
Definition 6.4 (Secure Boot)

Secure Boot is a function of the UEFI firmware that runs a boot program only if it carries a valid digital signature whose verification key is stored in the firmware as trusted and has not been revoked. Secure Boot is a check of authenticity, not encryption: it hides nothing, it only prevents modified or unknown boot programs from starting.

Windows device encryption
Definition 6.5 (BitLocker, recovery key)

BitLocker is the drive encryption of Windows; in Windows Home, it is called device encryption. It encrypts drive C:, and Windows decrypts it by itself at startup if the boot chain is unchanged. If the boot chain has been changed, Windows demands the recovery key, a 48-digit number that was generated when the encryption was switched on.

The live system

The live system
Definition 8.2 (Live system)

A live system is an operating system that starts and runs entirely from a removable storage device without mounting the computer's built-in storage devices. Its system is stored write-protected on the removable storage device; all changes during the session end up in main memory.

The compressed image: squashfs
Definition 8.3 (squashfs)

squashfs is a file system that stores its entire contents compressed in a single file and can only be read, not written to. It is created once, when the image is built.

A file system in main memory: tmpfs
Definition 8.4 (tmpfs)

tmpfs is a file system whose files are in main memory. It can be read and written to like any other file system. Its contents disappear as soon as it is unmounted or the computer is switched off.

Two layers on top of each other: the overlay
Definition 8.5 (Overlay)

An overlay places two file systems on top of each other and shows them as one: a lower, read-only layer and an upper, writable layer. When a file is read, it first looks in the upper layer and, if the file is missing there, in the lower one. If a file of the lower layer is to be changed, it first copies the file to the upper layer and changes the copy there. If a file of the lower layer is deleted, it enters a marker in the upper layer that hides the file. The lower layer remains unchanged in every case.

Persistence
Definition 8.6 (Persistence)

For a live system, persistence means that it stores changes not in main memory but in an additional storage area on the stick, so that they survive the restart. In Ubuntu, this is a partition or file labeled casper-rw, which the live system uses as the upper layer when it is started with the boot option persistent.

The live USB stick: preparing, writing, starting

Fast Startup in Windows
Definition 9.1 (Fast Startup)

Fast Startup is a function of Windows that, when shutting down, ends the programs but writes the state of the Windows kernel and its drivers to a file on drive C: and resumes from there at the next power-on instead of starting anew. It is switched on by default in Windows and takes effect only when shutting down, not with “Restart”.

The writing tool
Definition 9.2 (Writing tool)

A writing tool is a program that writes an image sector by sector onto an entire storage device. In doing so, it replaces the partition table and all the data of the storage device; whatever was on it before is lost afterward.

Key points so far

The answer in three sentences

  1. On Windows, you get a Linux of your own to practice on in three ways: with WSL 2 as a small VM alongside Windows, with a virtual machine in VirtualBox or as a live system from a USB stick.

  2. All three protect Windows because there is a boundary between the Linux you practice on and the Windows data: the hypervisor for WSL 2 and the VM, and main memory instead of the SSD for the live system.

  3. It becomes dangerous only where you cross this boundary yourself, when writing to a storage device and when changing the boot chain, and what helps against this is a checked image, the correctly identified stick, the unchanged start via the boot menu and a backed-up recovery key.

Chapter 2: The Shell: First Commands

Terminal and shell

The terminal emulator
Definition 1.1 (Terminal emulator)

A terminal emulator is a program that shows a window with lines of text, passes each keystroke as a character to another program and displays in the window each character that this program sends back. It does not understand what the characters mean.

The shell
Definition 1.2 (Shell)

A shell is a program that accepts commands as text, runs them or has other programs run them, and then waits for the next command. It shows the prompt as soon as it is ready for the next command.

The prompt
Definition 1.3 (Prompt)

The prompt is the text that the shell writes at the start of a line when it is ready to read the next command. In Ubuntu, it consists of the user name, the character @, the name of the computer, a colon, the current folder and an end character.

The session
Definition 1.4 (Session)

A session is the time from the start of a shell in a terminal until its end. Each session has its own current folder and its own list of the commands typed so far; two sessions know nothing about each other.

The structure of a command line

The command line
Definition 2.1 (Command line and word)

A command line is everything you type after the prompt before you press Enter. The shell splits it at spaces into words; several spaces in a row separate like a single one.

The command
Definition 2.2 (Command)

The first word of a command line is the command: the name of what is to be run. The shell looks up only this word; it passes all the others on to the command.

The argument
Definition 2.3 (Argument)

Every word of the command line after the command is an argument. The shell passes the arguments to the command in the order in which they appear. What an argument means is determined by the command itself.

The option
Definition 2.4 (Option)

An option is an argument that begins with a minus sign and determines how the command works. A short option consists of a minus sign and a single letter, such as -r. Several short options without a value may be bundled behind a single minus sign: -srm means the same as -s -r -m.

The long option
Definition 2.5 (Long option)

A long option begins with two minus signs followed by a whole word, such as --kernel-release. Many short options have an equivalent long form. Long options cannot be bundled; each one is a word of its own.

The option with a value
Definition 2.6 (Option with a value)

An option with a value requires an additional piece of information, such as a number. With a short option, the value follows as the next word or is attached directly: -n 2 or -n2. With a long option, it follows an equals sign or comes as the next word: --lines=2 or --lines 2.

The end of options
Definition 2.7 (End of options)

The argument --, two minus signs on their own, ends the options. The program treats all the words after it as ordinary arguments, even if they begin with a minus sign. The -- itself does not count as an argument.

Typical typing mistakes

  • ⁠Forgotten space: uname-r is a single word and thus an unknown command.

  • ⁠One space too many: uname - r passes a lone minus sign and an r; uname knows neither of them and reports an error.

  • ⁠Upper and lower case mixed up: UNAME is a different name from uname, and -R is a different option from -r.

  • ⁠Wrong slash: Linux separates folders with /, not with \ as Windows does.

Kinds of commands

The program file
Definition 3.1 (Program file)

A program file is a file that contains an executable program. Most commands are program files; on Linux, they are mainly in the folder /usr/bin.

The search path
Definition 3.2 (Search path)

The search path is the list of folders in which the shell looks for a program file with the name of the command; it starts the first one it finds. On Ubuntu, it includes /usr/local/bin, /usr/bin and /bin, among others.

The builtin command
$ which cd
↗
Definition 3.3 (Builtin command)

A builtin command is a command that the shell runs itself, without starting another program. Its program code is part of the shell, not of a file of its own.

The alias
$ type ls
↗
Definition 3.4 (Alias)

An alias is a name that the shell replaces with a stored text while reading a command line if the name stands at the start as a command. Only then does the shell search for the command at the front of the replaced text.

Finding help

The short help
Definition 4.1 (Short help)

The short help is a brief description that a program outputs when you call it with the option --help. It names the usage and the options, each with one line of explanation; then the program ends without doing anything else.

Help for builtins
Definition 4.2 (help)

The builtin command help shows the instructions for the shell's builtin commands. With a name as an argument, it describes that command; with the option -d, in a single line; without an argument, it lists all builtin commands.

The manual page
Definition 4.3 (Manual page)

A manual page, or man page for short, is the detailed description of a command, a file format, a system call or another part of the system, collected in the manual that every Linux comes with. The command man with the name as an argument displays it.

The pager
Definition 4.4 (Pager)

A pager is a program that shows a long text one screen at a time and lets you scroll and search in it. man passes every manual page to a pager; on Linux, this is usually the program less.

The sections of the manual
Definition 4.5 (Section of the manual)

The manual is divided into numbered sections, one for each kind of content (Table 3). You write a page together with its section as name(number), for example uname(1) for the command and uname(2) for the system call. man with a number before the name shows the page from that section; without a number, it shows the first page it finds, searching in a fixed order that starts with section 1.

Searching the manual
Definition 4.6 (apropos)

The command apropos searches the names and short descriptions of all manual pages for a keyword and lists the hits with their section. man -k does the same.

Working faster: completion, history, keyboard shortcuts

Completion
Definition 5.1 (Completion)

Completion finishes a partly typed word as soon as you press the Tab key. In the first word of a line, the shell completes command names; in the other words, mostly file names. If only one name fits, it writes it out in full; if several fit, it completes only the part they all have in common, and pressing the key a second time lists all the possibilities.

The history
Definition 5.2 (History)

The history is the numbered list of recently typed command lines that the shell keeps in its memory. The Up arrow key brings back the previous line, and each further press an older one; the Down arrow key goes forward again. The builtin command history shows the list. At the end of the session, bash writes the history to the file .bash_history in your home folder, and the next session reads it back in from there.

Reverse search
Definition 5.3 (Reverse search)

The reverse search searches the history from the newest line to the oldest for the text you type; you start it with Ctrl+R. Each further character narrows the search, and each further Ctrl+R jumps to the next older hit. Enter runs the command found, an arrow key takes it over for editing, and Ctrl+G cancels the search.

Interrupting with Ctrl+C
Definition 5.4 (Interrupting with Ctrl+C)

The key combination Ctrl+C asks the program that is currently running in the terminal to stop immediately; almost all programs then stop, and the shell shows the prompt again. If no program is running, Ctrl+C discards the partly typed line. When you press it, ^C appears in the window.

The end of input with Ctrl+D
Definition 5.5 (End of input with Ctrl+D)

The key combination Ctrl+D at the start of a line tells the program that is currently reading that no more input follows. A program that reads until the end of input is then finished. The shell itself also reads input; Ctrl+D on an empty command line therefore ends the session like exit.

Keyboard shortcuts for the command line
Definition 5.6 (Command-line keyboard shortcuts)

A keyboard shortcut of the command line is a key combination that the shell does not write into the line as a character but carries out as an instruction to edit the line or the window. Table 4 lists the most important ones.

Two implementations of the core commands: GNU and uutils

The core commands: coreutils
Definition 7.1 (coreutils)

The coreutils (“core utilities”) are a collection of over a hundred basic commands for files, text and system information, including ls, cat, head, cp, uname, date and df. The classic implementation comes from the GNU project and is called GNU coreutils.

uutils: the rewrite in Rust
$ ls --version
↗
Definition 7.2 (uutils coreutils)

uutils coreutils, uutils for short, is a rewrite of the coreutils in the programming language Rust that is meant to behave like the GNU implementation. The open source project has existed since 2013. Ubuntu has used it for most core commands since release 25.10; in Ubuntu 26.04, only cp, mv, rm, df and true still come from GNU coreutils.

Running the GNU implementation
Definition 7.3 (The prefix gnu)

Ubuntu 26.04 also installs the GNU implementation of the coreutils, under names with the prefix gnu: gnuls is GNU's ls, gnuuname its uname, gnudate its date and so on.

Key points so far

The answer in three sentences

  1. You talk to a computer that understands only text through the shell: it reads a command line, splits it into words, finds the command as an alias, builtin command or program file and has it run.

  2. What the words are and what they mean is defined by each program itself, following common conventions for options and arguments; you can look it up at any time with --help, help or man.

  3. Completion, history and keyboard shortcuts save typing, and just a few commands reveal the kernel, distribution, user, memory and disk space of your own system.

Chapter 3: Files, Directories and Paths

Files, directories and the directory tree

The file
Definition 1.1 (File)

A file is a sequence of bytes that is stored permanently under a name. What the bytes mean, whether text, image or program, is not determined by the system but by the program that reads the file.

The directory
Definition 1.2 (Directory)

A directory is a list of entries. Each entry links a name to a file or to another directory.

The directory tree and the root
Definition 1.3 (Directory tree, root directory)

The directories of a Linux system form a single directory tree: every directory except one is entered under its name in exactly one other directory. The one directory that is not entered in any other is called the root directory; it is written as a single slash /.

The working directory and paths

The working directory
Definition 2.1 (Working directory)

The working directory of a running program is the directory in which it is currently working. If you do not give a command a location, it refers to this directory.

The path
Definition 2.2 (Path)

A path is a sequence of names, separated by slashes /, that describes the route through the directory tree to a file or a directory. Every name except the last must denote a directory.

The absolute path
Definition 2.3 (Absolute path)

An absolute path begins with /. It describes the route from the root directory and therefore denotes the same location from every working directory.

The relative path
Definition 2.4 (Relative path)

A relative path does not begin with /. It describes the route from the working directory; which location it denotes therefore depends on where you currently are.

The special names . and ..
Definition 2.5 (The entries . and ..)

Every directory contains two special entries: . (one dot) denotes the directory itself, .. (two dots) its parent directory. In the root directory, .. denotes the root directory itself.

The home directory and the tilde
Definition 2.6 (Home directory)

A user's home directory is the directory that belongs to them for their own files. On Linux, it is usually /home/<name>, so for the user student, it is /home/student.

Changing the directory: cd
Definition 2.7 (cd)

The builtin command cd (short for “change directory”) makes the directory that its argument denotes the shell's new working directory. Without an argument, it changes to the home directory; with the argument -, it changes back to the previous working directory.

Showing the contents of a directory

The command ls
Definition 3.1 (ls)

The command ls prints, for each directory given as an argument, the names of its entries, sorted by name, and for every other file its name. Without an argument, it shows the working directory.

The hidden file
Definition 3.2 (Hidden file)

A hidden file is a file or directory whose name begins with a dot. ls shows such entries only with the option -a (short for “all”); -A shows them as well but leaves out . and ...

The type of an entry: ls -F
Definition 3.3 (ls -F)

With the option -F (long form --classify), ls appends a character to each name that reveals the type of the entry: / for a directory, * for an executable file, that is, a program, and a few other characters for rarer types. Regular files get no character.

The long format: ls -l
Definition 3.4 (ls -l)

With the option -l (short for “long”), ls prints each entry on a line of its own with seven pieces of information: type and permissions, a number, owner, group, size in bytes, the time of the last modification of the contents and name.

$ ls -l /usr/bin/bash
$ ls -ld /etc
↗
Human-readable sizes: ls -h
Definition 3.5 (ls -h)

Together with -l, the option -h (short for “human-readable”) makes ls print each size in the largest suitable unit: K for 1024 bytes, M for $1024^2$ bytes, G for $1024^3$ bytes. Below 10, there is one decimal place, and rounding is always up.

File names
Theorem 3.6 (Rules for file names)

A file name on Linux may contain any character except the slash / and the null byte, the byte with the value 0; on the usual file systems such as ext4, it is at most 255 bytes long. Uppercase and lowercase letters are distinct: Brief.txt and brief.txt are two files. A file name extension such as .txt or .jpg is just part of the name; the system does not interpret it.

Viewing files

Showing the entire contents: cat
Definition 4.2 (cat)

The command cat reads the files given as arguments in turn and writes out their bytes unchanged, one after the other.

Reading page by page: less
Definition 4.3 (less with a file)

If less receives a file as an argument, it shows the file's contents page by page. It does not change the file and does not load it all at once; that is why it opens even very large files immediately.

Beginning and end: head and tail
Definition 4.4 (head, tail)

The command head writes out the first lines of a file, the command tail the last ones. Without an option, it is ten lines each; with the option -n and a number, you set how many.

Counting: wc
Definition 4.5 (wc)

The command wc (short for “word count”) prints three numbers for each file named: the number of lines, counted as the number of line ends, the number of words, that is, of the character sequences between spaces, tabs and line ends, and the number of bytes. With -l, -w or -c, it prints only lines, words or bytes.

Determining the file type: file
Definition 4.6 (file)

The command file examines each file named and describes what it contains, such as text, an image in a particular format, a program or a directory. It judges by the contents, not by the name.

Creating files and directories

Creating a directory: mkdir
Definition 5.1 (mkdir)

The command mkdir (short for “make directory”) creates a new, empty directory for each argument. The parent directory must already exist, and the name must not already be taken in it.

Creating an empty file: touch
Definition 5.2 (touch)

The command touch sets the time of the last modification and of the last access of each file named to the current time. If the file does not exist yet, it creates it as an empty file with 0 bytes.

The text editor nano
Definition 5.3 (Text editor, nano)

A text editor is a program with which you create and change text files; it stores only the characters, no font and no formatting. nano is a simple text editor that runs in the terminal and constantly shows the most important shortcuts at the bottom edge.

The tree at a glance: tree
Definition 5.4 (tree)

The command tree draws the directory tree starting at the directory named, or without an argument starting at the working directory, with lines for the levels, and at the end counts the directories and files. With -a, it also shows hidden entries.

$ sudo apt install tree

Copying, moving, deleting

Copying: cp
Definition 6.1 (cp)

The command cp (short for “copy”) copies a file: cp source target creates a new file with the same contents under the name target. If target is an existing directory, the copy lands in it under the old name. If you name several sources, the last argument must be a directory.

Copying directories: cp -r
Definition 6.2 (cp -r)

With the option -r (short for “recursive”), cp copies a directory together with everything in it, level by level. If the target does not exist yet, it becomes the copy; if the target is an existing directory, the copy lands in it.

Moving and renaming: mv
Definition 6.3 (mv)

The command mv (short for “move”) gives a file or a directory a new name or a new location: mv source target renames source to target. If target is an existing directory, mv moves the source into it and keeps its name.

Deleting: rm
Definition 6.4 (rm)

The command rm (short for “remove”) removes the named files from their directories, immediately and usually without asking. There is no command that undoes this. Without a further option, rm leaves directories alone.

Deleting directories: rmdir and rm -r
Definition 6.5 (rmdir, rm -r)

The command rmdir (short for “remove directory”) removes a directory only if it is empty. rm with the option -r removes a directory together with everything in it, level by level and without asking.

Patterns for file names
Definition 6.6 (File name pattern)

A pattern is a word of the command line that contains one of the characters *, ? or [. Before the command starts, the shell replaces it with all matching names, sorted by name. Here * stands for any sequence of characters, even none, ? for exactly one arbitrary character, [abc] for exactly one of the characters in the brackets, [0-9] for exactly one from a range and [!abc] for exactly one character that is not in the brackets.

The directory structure of Linux

The standard for the directory structure
Definition 7.1 (Filesystem Hierarchy Standard)

The Filesystem Hierarchy Standard, FHS for short, specifies which directories a Linux system should have and which kind of files belongs in which of them. The current version, 3.0, appeared in 2015; today it is maintained by freedesktop.org, a joint project of open source developers.

Programs and libraries: /usr
Definition 7.2 (/usr)

The directory /usr contains the programs, libraries and unchanging data that come with the distribution. The programs are in /usr/bin, programs for system administration in /usr/sbin, libraries in /usr/lib and data such as manual pages and documentation in /usr/share.

Configuration: /etc
Definition 7.3 (/etc)

The directory /etc contains the configuration that applies to the whole system. Almost all files in it are text files that you can read and, with administrator privileges, change in a text editor.

The users: /home and /root
Definition 7.4 (/home, /root)

The directory /home contains a home directory for each ordinary user, named after that user. The home directory of root is kept apart from it in /root.

Variable data: /var and the logs
Definition 7.5 (/var, log file)

The directory /var (short for “variable”) contains data that change while the system is running. An important part of it is /var/log with the log files: files to whose end a program continuously writes what happens, each entry with the date and time.

Temporary files: /tmp
Definition 7.6 (/tmp)

The directory /tmp is intended for temporary files. Every user may create files there; when the system restarts, the contents may disappear.

Devices as files: /dev
Definition 7.7 (Device file)

A device file is an entry in the directory tree behind which there are no stored contents but a device that a driver in the kernel manages. Reading from it or writing to it means talking to this device. The device files are in /dev.

The kernel as a file system: /proc and /sys
Definition 7.8 (Virtual file system)

A virtual file system is a file system whose files are not on any storage device; the kernel creates their contents at the moment a program reads them. /proc is such a file system with information about the kernel and about every running program, /sys one with information about devices and drivers.

Inodes and links

The inode
Definition 8.1 (Inode)

An inode is the administrative record of a file in the file system. It contains all the information about the file except its name: type, permissions, owner and group, size, timestamps, the number of its names and the location of the blocks in which the contents are stored. Each inode has a number, the inode number, which is unique within a file system.

The directory as a table
Theorem 8.2 (Directory entry)

An entry in a directory consists of a name and an inode number. The size, the owner and all other information are in the inode to which the number points.

The hard link
Definition 8.3 (Hard link, link count)

A hard link is a further directory entry for an existing inode, that is, an additional name for the same file. The command ln target name creates it. The inode keeps count of how many entries point to it; this number is called the link count.

$ ls -ld rezepte rezepte/kuchen
↗
Deleting means removing a name
Theorem 8.4 (Deleting)

rm removes only the named directory entry and decreases the link count of the inode by 1. Only when the count is 0 and no running program still has the file open does the file system free the inode and its data blocks.

$ ls -i liste.txt
$ mv liste.txt einkauf.txt
$ ls -i einkauf.txt
↗
The symbolic link
Definition 8.5 (Symbolic link)

A symbolic link is a file of its own of type l whose only contents are a path. Almost every access to the link is redirected to the location that this path denotes. The command ln -s target name creates it.

A symbolic link in the system: /bin
Definition 8.6 (usr-merge)

The usr-merge, the merging of /usr, is the arrangement common today in which the directories /bin, /sbin and /lib are symbolic links to usr/bin, usr/sbin and usr/lib. All programs and libraries are then located under /usr.

Storage devices and mounting

Showing the storage devices: lsblk
Definition 9.1 (lsblk)

The command lsblk (short for “list block devices”) lists the storage devices and their partitions, that is, the device files of type b, with size, type and the directories at which their file systems are mounted.

What is mounted where: findmnt
Definition 9.2 (findmnt)

The command findmnt lists the mounted file systems with mount point (TARGET), source (SOURCE), type (FSTYPE) and options (OPTIONS). With -T path, it names only the file system in which the path is located, with -t type only file systems of one type, and with -o, you choose the columns.

How full a file system is: df with paths
Definition 9.3 (df with paths)

If df receives paths as arguments, it shows for each path the file system in which it is located, with size, used and free space. The option -T adds the type of the file system.

The Windows drive under WSL 2: /mnt/c
Definition 9.4 (/mnt/c under WSL 2)

Under WSL 2, the Windows drive C: is mounted at /mnt/c, as a file system of type 9p. Every access to it is passed on as a request to a file server in Windows, which reads or writes the file on the Windows drive.

Finding files and measuring space

Searching with find
Definition 10.1 (find)

The command find walks through the subtree below each given starting directory, entry by entry and level by level. For each entry, it checks the conditions that follow the starting directories, the so-called tests, and prints the path of every entry that passes all tests. Without tests, it prints every entry.

Searching by name: -name
Definition 10.2 (-name, -iname)

The test -name pattern passes if the name of an entry, that is, the last part of its path, matches the pattern; the pattern follows the same rules as in subsection 6.6. The test -iname does the same but does not distinguish between uppercase and lowercase letters.

Searching by type: -type
Definition 10.3 (-type)

The test -type type passes if an entry is of the given type: f for a regular file, d for a directory, l for a symbolic link, b and c for device files.

Searching by size: -size
Definition 10.4 (-size)

The test -size n compares the size of an entry with n; +n means greater than n, -n less than n, and n alone exactly n. A letter after the number gives the unit: c for bytes, k for 1024 bytes, M for $1024^2$, G for $1024^3$; without a letter, the old unit of 512 bytes applies. Before comparing, find rounds the size up to whole units.

Searching by age: -mtime, -mmin and -newer
Definition 10.5 (-mtime, -mmin, -newer)

The test -mtime n compares the age of the last modification in whole days of 24 hours with n; partial days are dropped, and +n and -n mean more and less, as with -size. -mmin n does the same in minutes. -newer file passes if an entry was modified later than the given file.

Combining tests and processing matches
Definition 10.6 (Combining, -maxdepth, action)

If several tests follow one another, an entry must pass all of them. A ! in front of a test negates it. The option -maxdepth n directly after the starting directories limits the search to n levels below the starting directory. What find does with a match is determined by an action; if none is given, it is -print, which prints the path.

Measuring disk usage: du
Definition 10.7 (du)

The command du (short for “disk usage”) adds up, for each given directory and each subdirectory in it, the space that the files occupy on the storage device, in units of 1024 bytes. With -s, it prints only the total for each argument, with -h human-readable units like ls -h.

Key points so far

The answer in three sentences

  1. Linux organizes all files in a single tree in which every location has a path and every additional storage device is mounted on a directory; the FHS defines which directory is for what.

  2. With paths and a few commands, you move through this tree, view files, create, copy, move and delete them, select many at once with patterns and find them again with find.

  3. A file name is just an entry in a directory that points to an inode; from this follow hard and symbolic links, the instant mv and the permanent rm.

Chapter 4: Streams, Redirection, Pipes and Exit Status

Processes and their three streams

The process
Definition 1.1 (Process)

A process is a program that is currently being executed, together with everything that belongs to exactly this execution: its own area in main memory, the files it has opened and its working directory. The kernel keeps each process separate from all others. It gives each process a number, the process ID.

The stream
Definition 1.2 (Stream, end of the stream)

A stream is a sequence of bytes that a process reads or writes in order. The process sees only the bytes themselves, not where they come from or where they go. If nothing more arrives during reading and nothing more can arrive, the end of the stream has been reached; the kernel tells the reading process by having a read request return zero bytes.

Standard input
Definition 1.3 (Standard input)

Standard input (stdin for short) is the stream from which a process reads when it is not told otherwise. If you start a program in the terminal, its standard input is the terminal: what you type arrives in this stream as a line once you press Enter.

Standard output
Definition 1.4 (Standard output)

Standard output (stdout for short) is the stream to which a process writes its results. If you start a program in the terminal, its standard output is the terminal, which displays everything that arrives there.

Standard error
Definition 1.5 (Standard error)

Standard error (stderr for short) is a second output stream to which a process writes error messages, warnings and notices. If you start a program in the terminal, this stream goes to the terminal, too.

The file descriptor
Definition 1.6 (File descriptor)

A file descriptor, descriptor for short, is a small integer under which the kernel keeps track of an open file for a process. The three standard streams have fixed numbers: 0 is standard input, 1 standard output, 2 standard error. Every further file that the process opens gets the lowest number that is currently free, so 3 comes first.

Redirecting output

$ mkdir ~/linuxk4
$ cd ~/linuxk4
↗
Output redirection: >
Definition 2.1 (Redirection, output redirection)

A redirection is an instruction to the shell to connect a descriptor of the new process to a different file before the program starts. The notation command > file connects standard output to the file file. If the file does not exist yet, the shell creates it; if it already exists, the shell empties it first.

$ cat > einkauf.txt
$ cat einkauf.txt
$ wc -c einkauf.txt
↗
$ > leer.txt
$ wc -c leer.txt
↗
$ cp einkauf.txt probe.txt
$ echo Tee > probe.txt
$ cat probe.txt
↗
Appending: >>
Definition 2.2 (Appending)

The notation command >> file connects standard output to the file for appending: every byte written goes after the existing contents, and nothing is deleted. If the file does not exist, the shell creates it.

$ echo Butter >> einkauf.txt
↗
Redirection of standard error: 2>
Definition 2.3 (Redirection of standard error)

The number of a descriptor may stand in front of > and >>, with no space in between. command 2> file redirects standard error into the file, and command 2>> file appends it to the file. Without a number, 1 applies: > means the same as 1>.

The file that swallows everything: /dev/null
Definition 2.4 (Discarding output)

command 2> /dev/null discards the messages of a program, command > /dev/null its results. The program notices nothing of this: every write request succeeds.

Copying a descriptor: 2>&1 and &>
Definition 2.5 (Copying a descriptor)

The notation n>&m makes descriptor $n$ a copy of descriptor $m$: afterward, $n$ leads to the same open file as $m$ at that moment. So 2>&1 means: standard error should lead to where standard output currently leads. Without a number in front of the symbol, 1 applies again: >&2 makes standard output a copy of standard error.

The order of redirections
Theorem 2.6 (Order of redirections)

The shell carries out the redirections of a command line from left to right, one after the other. With 2>&1, descriptor 2 takes over the target that descriptor 1 has at exactly that moment; later redirections of descriptor 1 no longer change anything about descriptor 2.

The truncation trap
Theorem 2.7 (Truncation trap)

With command file > file, the file is empty before the command starts. The shell sets up the redirection before the program starts, and > empties the file in the process. The program then reads an empty file; the old contents are lost.

$ sort probe.txt > sortiert.txt
$ mv sortiert.txt probe.txt
$ cp einkauf.txt probe2.txt
$ sort -o probe2.txt probe2.txt
$ cat probe2.txt
↗

Redirecting input

Input redirection: <
Definition 3.1 (Input redirection)

The notation command < file opens the file for reading and connects it to the standard input of the new process. The program gets no file name, only the stream.

The here document
Definition 3.2 (Here document)

A here document is a redirection of the form command <<ENDMARKER, followed by lines of text and finally a line that contains only the end marker. The shell collects the lines in between and gives them to the command as standard input; the line with the end marker is not part of it.

$ cat > obst.txt <<ENDE
$ wc -l obst.txt
↗
The here string
Definition 3.3 (Here string)

A here string is a redirection of the form command <<< "text". The shell gives the command the text as standard input and appends a line end.

Pipes and filters

The pipe
$ ls /usr/bin > liste.txt
$ wc -l < liste.txt
$ rm liste.txt
↗
Definition 4.1 (Pipe)

A pipe connects the standard output of one process to the standard input of another. The notation command1 | command2 tells the shell to start both programs at the same time, each in a process of its own, and to connect descriptor 1 of the first to descriptor 0 of the second. The bytes pass through a buffer in the kernel, not through a file.

$ ls > wc
$ ls
$ rm wc
↗
The filter
Definition 4.2 (Filter)

A filter is a program that reads data from its standard input, transforms it and writes the result to its standard output. Most filters read files instead if you give them their names as arguments.

The pipeline
Definition 4.3 (Pipeline)

A pipeline is a sequence of commands connected by |. The shell starts all commands at the same time, each in a process of its own, and connects the standard output of each command to the standard input of the next. The standard output of the last command leads where it would have led without a pipeline; it can be redirected like any other.

The branch: tee
Definition 4.4 (tee)

The command tee reads its standard input and writes everything it reads both to its standard output and to every file named as an argument. It creates these files or empties them first; with the option -a, it appends.

The Unix philosophy
Definition 4.5 (Unix philosophy)

The Unix philosophy is a principle for building programs. Each program should do one thing well. Programs should read and write text, without unnecessary extras, so that the output of every program can become the input of another. You solve new tasks by connecting existing programs instead of writing a big new one.

The exit status

The exit status
Definition 5.1 (Exit status)

When it ends, every process leaves behind an integer from 0 to 255, its exit status. The number 0 means success, every other number means failure. The shell, which has waited for the process to end, receives the number from the kernel and remembers it until the next command ends.

$ bash -c 'exit 3'
$ echo $?
$ bash -c 'exit 300'
↗
What the nonzero numbers mean
Theorem 5.2 (Meaning of the nonzero numbers)

Which nonzero number means which failure is determined by each program itself; the manual page describes it in its EXIT STATUS part (Chapter 2, Section 4.3). Many programs report every failure with 1. Programs that distinguish several kinds usually use 1 for a “no” result or a minor error and 2 for a serious error or an incorrect call.

The shell's numbers: 126, 127 and 128 + n
Definition 5.3 (Exit statuses set by the shell)

The shell itself sets an exit status in three cases:

  • 127 if the command does not exist;

  • 126 if the file does exist but cannot be executed as a program;

  • $128 + n$ if the process was ended by the interrupt message with the number $n$.

Chaining commands

One after another: the semicolon
Definition 6.1 (Semicolon)

The notation command1 ; command2 first runs command1, waits until it ends and then runs command2, regardless of the exit status with which command1 ended. The exit status of the whole line is that of the last command.

Only on success: &&
Definition 6.2 (AND list)

The notation command1 && command2 is an AND list: the shell runs command2 only if command1 ended with exit status 0. The exit status of the AND list is that of the last command executed.

Only on failure: ||
Definition 6.3 (OR list)

The notation command1 || command2 is an OR list: the shell runs command2 only if command1 ended with a nonzero exit status. The exit status of the OR list is that of the last command executed.

&& and || in one line
Theorem 6.4 (Evaluation of && and ||)

&& and || have equal precedence and are evaluated from left to right. a && b || c therefore means: first a && b as a whole, then c if this whole failed. So c runs if a fails, and also if a succeeds and b fails.

The exit status of a pipeline
Theorem 6.5 (Exit status of a pipeline)

The exit status of a pipeline is the exit status of its last command. If the setting pipefail is turned on, it is instead the exit status of the rightmost command that failed, or 0 if all of them succeeded.

Turning output into arguments

Stream or argument
Theorem 7.1 (Stream and argument)

A pipe connects streams, not arguments. What comes through the pipe is in the standard input of the next program and never in its argument list. A program that does not read its standard input sees none of it; a filter treats it as data, not as file names.

The command xargs
Definition 7.2 (xargs)

The command xargs reads its standard input and splits it into words at spaces, tabs and line ends. Then it starts the command that follows it as arguments and appends these words at the end as additional arguments. Without a command, it uses echo.

Batches: xargs -n and the argument list limit
Definition 7.3 (Argument list limit, xargs -n)

The kernel limits how many bytes all the arguments of a program start may have together; getconf ARG_MAX shows this argument list limit. xargs keeps to it on its own and starts the command as often as necessary. With -n number, it passes at most number words per call.

Names with spaces: the null byte as a separator
Definition 7.4 (-print0 and xargs -0)

The action -print0 of find writes a null byte, that is, the byte with the value 0, after each match instead of a line end. The option -0 makes xargs split its input only at null bytes; spaces and line ends then belong to the name.

$ echo "Gabi's Café.jpg" | xargs ls
↗
The way without a pipe: find -exec
Definition 7.5 (-exec)

The action -exec command {} \; of find starts the command once for each match and puts the name of the match in place of {}. The action -exec command {} + collects the names like xargs and starts the command as rarely as possible, with many names at once; here {} must stand directly before the +.

Key points so far

The answer in three sentences

  1. Every program runs as a process with three standard streams that it knows only by the numbers 0, 1 and 2; where they lead is set by the shell before the start.

  2. With redirections, you connect them to files, with pipes to other programs, and in this way small filters become tool chains that together answer questions for which no dedicated program exists.

  3. From the exit status, the shell recognizes success and failure and, with && and ||, makes the next step depend on it.

Chapter 5: How the Shell Reads a Command Line: Expansion, Quoting, Variables, Environment

Expansion: patterns, braces and the tilde

Expansion
Definition 1.1 (Expansion)

Expansion is the step in which the shell replaces certain parts of the words of a command line with other text. It happens after the shell has split the line into words and before it executes the command; the program receives only the result as its arguments.

Pathname expansion
Definition 1.2 (Pathname expansion)

Pathname expansion is the expansion that replaces a pattern with the names of the existing files and directories that it matches; each match becomes a word of its own. The matches appear sorted. If the pattern contains slashes, the shell checks each part of the path separately; a slash must appear in the pattern itself, because *, ? and […] never stand for it.

Hidden files and patterns
Theorem 1.3 (Hidden files in patterns)

A name that begins with a dot matches a pattern only if the pattern itself has a dot at this position, that is, at its beginning or directly after a slash. With its default settings, bash never returns the entries . and .. as matches.

A pattern with no match
Theorem 1.4 (Pattern with no match)

If a pattern matches no name, the shell leaves the word unchanged. The program then receives the pattern as ordinary text.

Brace expansion
Definition 1.5 (Brace expansion)

Brace expansion turns a word with curly braces into several words. Inside the braces is either a list with commas, {a,b,c}, or a sequence {x..y} or {x..y..s} of integers or single letters, with the step $s$. Each element of the list or sequence yields one word; what stands in the word before the braces goes in front of each element, what stands after them goes behind each one. The words appear in the written order, not sorted.

$ mkdir -p urlaub/{2025,2026}/{sommer,winter}
$ echo urlaub/*/*
↗
Tilde expansion
Definition 1.6 (Tilde expansion)

Tilde expansion replaces a tilde at the beginning of a word. Everything from the tilde up to the first slash or to the end of the word is evaluated: if nothing follows the tilde, the shell inserts the path of your home directory; if a user name follows, it inserts the path of that user's home directory. If there is no such user, the text stays unchanged; a tilde in the middle of a word, as a rule, stays as it is too.

Variables, command substitution and arithmetic expansion

The shell variable
Definition 2.1 (Shell variable, assignment)

A shell variable is a name under which the running shell stores a text, the value of the variable. You create a variable or change its value with an assignment of the form NAME=value; there is no space before or after the equals sign. The name consists of letters without umlauts or other accents, digits and the underscore, and it does not begin with a digit; uppercase and lowercase letters are different.

Parameter expansion: $NAME and ${NAME}
Definition 2.2 (Parameter expansion)

Parameter expansion replaces $NAME or ${NAME} with the value of the variable. Without curly braces, the shell takes as many characters for the name as a name can have; with braces, the name ends at the closing brace. If the variable has no value, the shell inserts empty text, without an error message.

Command substitution
Definition 2.3 (Command substitution)

Command substitution $(command) executes the command in the parentheses in a separate process and replaces itself with that command's standard output. In doing so, the shell removes line ends at the end of the output.

Arithmetic expansion
Definition 2.4 (Arithmetic expansion)

Arithmetic expansion $((expression)) computes the expression in the double parentheses with integers and inserts the result as text. Allowed are, among others, +, -, * (times), / (divided by), % (remainder of the division), ** (to the power of) and parentheses; multiplication and division come before addition and subtraction. / drops the remainder. In the expression, you refer to variables by their name; a $ is not needed there.

Word splitting and quoting

Showing arguments one by one: printf
Definition 3.1 (printf)

The builtin command printf writes text according to a format, its first argument. In the format, %s stands for the next argument and \n for a line end. If arguments are still left after the pass through the format, printf applies the format again.

Word splitting
$ echo $(cat einkauf.txt)
$ touch "mein bericht.txt"
$ datei="mein bericht.txt"
$ ls $datei
↗
Definition 3.2 (Word splitting)

Word splitting splits the results of parameter expansion, command substitution and arithmetic expansion into separate words, provided these expansions were not within double quotes. The splitting happens at spaces, tabs and line ends; several of them in a row count as one, and at the beginning and at the end they are dropped. Text that you typed yourself is not split a second time by word splitting.

Quoting
Definition 3.3 (Quoting)

Quoting means marking characters of a command line so that the shell takes them literally instead of giving them a special meaning. The three basic means for this are single quotes, double quotes and the backslash. What is marked in this way stays together when the line is split into words.

Single quotes
Definition 3.4 (Single quotes)

Between single quotes '…', the shell takes every character literally. No expansion takes place, and everything in between stays one word. A single quote itself cannot occur inside them, not even with a backslash in front of it.

Double quotes
Definition 3.5 (Double quotes)

Between double quotes "…", the shell takes all characters literally except three: $ still introduces a parameter expansion, a command substitution or an arithmetic expansion, ` a command substitution in the old notation, and \ still has an effect before $, `, ", \ and the line end. Word splitting, pathname expansion, tilde expansion and brace expansion do not take place; the whole stays one word.

The backslash
Definition 3.6 (Backslash)

A backslash \ outside of quotes removes the special meaning of the character directly after it. If it stands at the end of a line, it joins that line with the next one into a single command line.

Quote removal
Definition 3.7 (Quote removal)

As the last step of expansion, the shell removes all quotes and backslashes that you typed and that are not themselves protected. Characters of this kind that only entered the line through an expansion, for example from the value of a variable, stay in place.

The rule: expansions in double quotes
Theorem 3.8 (Rule for quoting)

Put every parameter expansion and every command substitution in double quotes, that is, "$datei" and "$(command)", unless you explicitly want its result to fall apart into words. Put text that a program is to receive unchanged, such as a pattern for find, in single quotes.

$ touch mein bericht.txt
$ ls
$ rm $datei
↗
The order of all steps
Theorem 3.9 (Order of expansion)

The shell processes a command line in this order:

  1. It splits the line into words, taking the quoting into account; if the first word is an alias, it replaces it (Chapter 2, Section 3.4).

  2. Brace expansion.

  3. Tilde expansion, parameter expansion, arithmetic expansion and command substitution, in one pass from left to right.

  4. Word splitting of the results from step 3 that are not within double quotes.

  5. Pathname expansion.

  6. Quote removal.

After that, it sets up the redirections (Chapter 4, Section 2) and runs the command.

$ printf "[%s]\n" -l {foto,notiz}* "$HOME"
↗

Environment and inheritance

The child process
Definition 4.1 (Child process, parent process)

If a process starts another one, the new process is a child process of the first. The starting process is called its parent process.

The environment
Definition 4.2 (Environment)

The environment of a process is a list of texts of the form NAME=value that the process receives when it starts, in addition to its arguments. Each program decides for itself which entries it takes into account.

The environment variable: export
Definition 4.3 (Environment variable, export)

An environment variable is a shell variable that is marked for passing on; the shell writes all marked variables into the environment of every child process. The builtin command export marks a variable: export NAME marks an existing one, export NAME=value assigns and marks in one step. Variables that the shell finds in its environment when it starts are marked from the beginning.

Inheritance as a copy
Theorem 4.4 (Inheritance of the environment)

A child process receives a copy of its parent process's environment when it starts. Whatever it changes in its variables afterward changes only its copy; none of it gets back to the parent process. Likewise, a later change in the parent process no longer reaches a child that is already running.

A variable for one command only
Definition 4.5 (Assignment before a command)

If one or more assignments NAME=value come before the command name, they go only into the environment of this one command. The shell itself keeps its variables as they were.

env and printenv
Definition 4.6 (env)

The command env starts a command with a modified environment. env NAME=value command adds entries, env -u NAME command leaves one out and env -i command starts the command with an empty environment. Without a command, env writes the environment like printenv.

How the shell finds programs: PATH

The variable PATH
Definition 5.1 (PATH)

The environment variable PATH contains the search path as text: the directories, separated by colons, in the order in which the shell searches them. An empty entry, that is, two colons in a row or a colon at the beginning or at the end, stands for the working directory.

Command search
Theorem 5.2 (Command search)

If the command name contains no slash, the shell, after checking for an alias, keyword, function and builtin command (Chapter 2, Section 3.5), goes through the directories from PATH from left to right and starts the first executable file with this name; it remembers the path it found for later. If it finds none, it reports the error and sets exit status 127. If the command name contains a slash, the shell does not search at all but starts exactly the file that the path designates.

A program in the working directory: ./
$ cp /usr/bin/tree ./meinbaum
↗
Theorem 5.3 (Program outside the search path)

You start a program that is not in any directory from PATH with a path that contains a slash: ./program in the working directory, otherwise with an absolute or relative path.

$ cp /usr/bin/date ./meindatum
$ ./meindatum -d 2026-12-24 +%A
$ cp /usr/bin/gnudate ./meindatum2
$ ./meindatum2 -d 2026-12-24 +%A
↗
Changing PATH
$ PATH=/gibtsnicht ls
$ ls notiz.txt

Startup files and aliases

The startup file
$ wohnort=Hamburg
$ bash -i -c 'echo Wohnort: $wohnort Ende'
↗
Definition 6.1 (Startup file)

A startup file is a text file with commands for the shell that the shell reads and runs when it starts, as if you had typed the lines. If you start a new interactive bash in a terminal, it reads the file ~/.bashrc in your home directory.

source
Definition 6.2 (source)

The builtin command source file reads the file and runs its lines in the running shell, as if you had typed them. A single dot is a short form: . file means the same.

The login shell
Definition 6.3 (Login shell)

A login shell is a shell that starts at a login, for example after a user name and password on a text console, for a connection from another computer or when you open the WSL terminal. bash then first reads /etc/profile and after that the first existing one of the files ~/.bash_profile, ~/.bash_login and ~/.profile; it does not read ~/.bashrc on its own.

Making a setting permanent

The alias
Definition 6.4 (Defining an alias)

The builtin command alias name='text' defines an alias: if name is the first word of a command, the shell replaces it with text. unalias name removes the alias, and alias without arguments shows all of them. Aliases apply only in the shell in which they were defined, and only in interactive shells.

$ echo "alias einkauf='cat ~/linuxk5/einkauf.txt'" >> ~/.bashrc
$ tail -n 1 ~/.bashrc
$ source ~/.bashrc

Key points so far

The answer in three sentences

  1. Before it starts a program, the shell replaces patterns, braces, tildes, variables, commands and calculations, splits the results into words and removes the quotes, in a fixed order; with quotes and the backslash, you determine which of this happens.

  2. The program receives the finished words as arguments and, in addition, a copy of the environment with all exported variables; it cannot pass any of it back.

  3. A program is found via the directories in PATH, and everything that a shell is to know every time it starts is in startup files such as ~/.bashrc.

Chapter 6: Text Tools and Regular Expressions

Text data: records, fields and line ends

Record and field
Definition 1.1 (Record, field)

A record is a line of a text file that contains the values of one table row. Its individual values are called fields; they stand one after the other in a fixed order. Between any two fields there is an agreed character, the separator. The fields of a record are counted from the left, starting with 1.

The CSV file and its header line
Definition 1.2 (CSV file, header line)

A CSV file is a text file in which each line is a record and the comma separates the fields. The name stands for “comma-separated values”. Often the first line contains the names of the columns instead of values; it is called the header line.

$ cat > laeufe.csv <<ENDE
$ head -n 3 laeufe.csv

The line end under Windows
Definition 1.3 (Carriage return, Windows line end)

The carriage return is an invisible character with the value 13, often written \r in programs. In text files, Windows ends every line with two bytes, the carriage return and the newline, that is, 13 and 10. Linux and the other Unix systems use only the newline.

$ printf '%s\r\n' datum,name,km,minuten 2026-11-02,Anna,5.0,28 2026-11-02,Ben,10.5,62 > windows.csv
$ cat windows.csv
$ cat -A windows.csv

$ head -n 3 laeufe.csv > drei.csv
$ wc -c drei.csv windows.csv

From a given line on: tail -n +K and head -n -K
Definition 1.4 (tail -n +K, head -n -K)

tail -n +K writes all lines from line number $K$ to the end. head -n -K writes all lines except the last $K$.

Following a growing file: tail -f
Definition 1.5 (tail -f)

tail -f file first writes the last lines of the file as usual. After that, it does not end but waits and writes everything that is later appended to the file as soon as it arrives there. It runs until you abort it with Ctrl+C.

Cutting out columns and replacing characters: cut, tr and paste

Cutting out columns: cut
Definition 2.1 (cut)

The command cut writes out only selected parts of each line of its input. With -d and a character, you set the separator; with -f and a list, the fields that are kept. The list consists of numbers and ranges, separated by commas: 2, 1,3, 2-4, 2- for “from field 2 on”. Without -d, the tab is the separator.

$ tail -n 3 laeufe.csv | cut -c9-10

Replacing and deleting characters: tr
Definition 2.2 (tr)

The command tr reads its standard input character by character and writes it out changed. tr set1 set2 replaces each character that stands at a certain position in the first set with the character at the same position in the second set. tr -d set deletes all characters of the set; tr -s set squeezes several identical characters of the set in a row into one.

$ tr a-z A-Z laeufe.csv

$ tr -d '\r' < windows.csv > linux.csv

Joining columns: paste
Definition 2.3 (paste)

The command paste reads several files at the same time and writes the first line of each file side by side in one line, then the second lines and so on. Between the parts, it puts a tab or, with -d, another character. With -s, it instead puts all lines of a file one after the other in a single line.

Sorting and counting: sort and uniq

How sort compares: the character order
Definition 3.1 (sort)

The command sort reads all lines of its input and writes them out in order. It compares two lines character by character from the left; the first character in which they differ decides, according to the order of the characters. If one line is the beginning of the other, the shorter one comes first. With -r, sort reverses the order.

$ printf '%s\n' 10 9 100 | sort -r
↗
Sorting numerically: sort -n
Definition 3.2 (sort -n)

With the option -n, sort reads a number at the beginning of each line, with an optional minus sign and an optional decimal point, and compares the lines by the value of this number. A line that does not begin with a number counts as the number 0. If the values are equal, the character order of the whole line decides.

Sorting by a column: -t and -k
Definition 3.3 (Sort key)

-t and a character set the separator at which sort splits the lines into fields. -k A,B makes the fields from number $A$ to number $B$ the sort key: sort compares only this piece of the line. Letters such as n or r directly after the specification, as in -k3,3n, apply only to this key. If ,B is missing, the key extends to the end of the line. Several -k are compared one after the other; if all keys are equal, the whole line decides.

The locale
Definition 3.4 (Locale)

The locale, the language setting, is a set of rules for a language and a country. Among other things, it determines which bytes together form a character, which characters are letters, in which order characters are sorted and which character is the decimal separator. A program learns it from environment variables, above all from LANG and LC_ALL; if LC_ALL is set, it takes priority.

Identical adjacent lines: uniq
Definition 3.5 (uniq)

The command uniq compares each line of its input with the line directly before it and, of several identical lines in a row, writes out only one. With -c, it puts in front of each output line how often it occurred in a row. -d outputs only lines that occurred several times in a row, -u only those that stood alone.

Counting frequencies: sort, uniq -c, sort -rn
Theorem 3.6 (Frequency table)

The pipeline sort | uniq -c | sort -rn turns a list of values, one per line, into a table of the different values with their frequency, the most frequent first. The first sort brings identical values together, uniq -c counts them, sort -rn orders by the count in descending order.

$ tail -n +2 laeufe.csv | cut -d, -f2 | sort -u
↗

Numbering, sequences of numbers and differences: nl, seq and diff

Numbering lines: nl
Definition 4.1 (nl)

The command nl writes out each line of its input with a running number in front of it, separated by a tab. Without an option, it numbers only lines that are not empty; with -ba, it numbers all of them.

Generating sequences of numbers: seq
Definition 4.2 (seq)

The command seq writes a sequence of numbers, one per line. seq end counts from 1 to end, seq start end from start to end, seq start step end in steps of the given size. The sequence ends with the last number that does not exceed end. -s sets a separator other than the line end, -w pads with leading zeros to equal width.

Finding differences: diff
Definition 4.3 (diff)

The command diff compares two text files line by line and outputs what you would have to change in the first one to get the second one. Each change begins with a line of line numbers and a letter: a for add, c for change, d for delete. Below it are the affected lines of the first file with < in front of them and those of the second with >. The exit status is 0 for identical files, 1 for differences and 2 for an error.

$ head -n 5 laeufe.csv > kurz.csv
$ head -n 5 laeufe.csv | tr B b > klein.csv

Searching with grep

Lines with a search text: grep
Definition 5.1 (grep)

After the options, the command grep receives a search text as its first argument and then files. It writes out every line of these files in which the search text occurs anywhere and leaves out the others. Without files, it reads its standard input. Its exit status is 0 if at least one line matched, 1 if none matched and 2 for an error.

Inverting, counting, numbering: -i, -v, -c and -n
Definition 5.2 (Options of grep)

-i ignores case in the comparison. -v inverts the selection and writes the lines in which the search text does not occur. -c writes only the number of lines instead of the lines themselves. -n puts in front of each output line its number in the file and a colon.

Outputting only the match: -o
Definition 5.3 (grep -o)

With the option -o, grep writes, instead of the whole line, only the pieces that match the search text, each on a line of its own. If the search text occurs several times in a line, several output lines result.

Searching in many files: -r and -l
Definition 5.4 (grep with several files, -r, -l)

If grep receives more than one file, it puts the file name and a colon in front of each output line. With -r, it searches all files in the given directories and their subdirectories. With -l, it writes, instead of the lines, only the names of the files in which it found something, each one once.

Regular expressions: characters, classes and anchors

The regular expression
Definition 6.1 (Regular expression, match)

A regular expression is a text that describes a set of strings. It consists of ordinary characters, which stand for themselves, and of special characters with a meaning of their own. A line matches a regular expression if a contiguous piece of it belongs to this set; this piece is called the match.

The dot: any single character
Definition 6.2 (Dot)

The dot . in a regular expression matches any single character.

Taking special characters literally: the backslash and grep -F
Definition 6.3 (Backslash in the expression, grep -F)

A backslash \ before a special character turns it into an ordinary character in a regular expression: \. matches only a dot. With the option -F, grep takes the whole search text as a fixed string in which no character has a special meaning.

A selection of characters: the bracket expression
Definition 6.4 (Bracket expression)

A bracket expression is a list of characters in square brackets; it matches exactly one character that is in the list. Two characters with a hyphen between them stand for all characters from the one to the other, such as [0-9] for a digit. If a ^ comes directly after the opening bracket, the expression matches exactly one character that is not in the list.

Character classes: [[:digit:]] and its relatives
Definition 6.5 (Character class)

A character class is a named group of characters that you write inside a bracket expression as [:name:]. Important names are digit for digits, alpha for letters, upper and lower for uppercase and lowercase letters, alnum for letters and digits, space for the space and related characters such as tab, newline and carriage return, blank only for space and tab, and punct for punctuation marks. Which characters belong to a class is determined by the locale.

Start and end of the line: the anchors
Definition 6.6 (Anchor)

An anchor matches not a character but a position in the line. ^ at the beginning of an expression matches the position before the first character of the line, $ at the end of an expression the position after the last character, directly before the line end.

Regular expressions: repetitions, groups and alternatives

Any number of times: the star
Definition 7.1 (Star)

A star * after an ordinary character, a dot or a bracket expression matches any number of repetitions of it in a row, including none at all.

The extended form: grep -E
$ grep ',[0-9]{3}$' laeufe.csv
$ echo $?
$ grep -E ',[0-9]{3}$' laeufe.csv
↗
Definition 7.2 (Basic form, extended form)

The basic form of regular expressions is the notation that grep uses without an option; it is called “basic regular expressions”, BRE for short. In it, the characters + ? { } ( ) | are ordinary characters. In the extended form, called “extended regular expressions”, ERE for short, they are special characters as well; grep -E turns it on.

Counting repetitions: +, ? and {n,m}
Definition 7.3 (Quantifier)

A quantifier stands after an element of an expression and determines how often the element may occur in a row. In the extended form, besides the star, there are: + for at least once, ? for zero times or once, {n} for exactly $n$ times, {n,m} for $n$ to $m$ times and {n,} for at least $n$ times.

Group and alternative
Definition 7.4 (Group, alternative)

Parentheses combine part of an expression into a group; a quantifier after the group acts on it as a whole. The vertical bar forms an alternative: a|b matches where a matches or where b matches. The bar binds more weakly than anything else: it splits the whole expression or the group in which it stands.

Basic form and extended form compared
Theorem 7.5 (Basic form and extended form)

What the extended form expresses with { } and ( ), the basic form writes with a backslash in front: \{n,m\} and \(…\). Whether \+, \? and \| are special characters in the basic form, the standard for Unix shells and their tools leaves to each tool; the GNU tools understand them that way. Conversely, in the extended form, a character such as + with a backslash in front is ordinary.

The longest match
Theorem 7.6 (Longest match)

Among all matches of an expression in a line, the one that begins furthest to the left counts. If there are several from this position on, the longest one counts.

Form, not meaning
$ printf '%s\n' 2026-11-09 2026-13-45 9.11.2026 | grep -E '^[0-9]{4}-[0-9]{2}-[0-9]{2}$'
↗
Theorem 7.7 (Form, not meaning)

A regular expression checks only which characters stand in which order. What these characters mean, whether a number is large or small, whether a date exists, it does not know. Every rule about meaning has to be translated, if this is possible at all, into rules about characters.

File name patterns and regular expressions
Theorem 7.8 (Pattern and regular expression)

A file name pattern is evaluated by the shell before a command starts; a regular expression is evaluated by the program, such as grep. In the pattern, * stands for any sequence of characters and ? for any single character; in the regular expression, * repeats the element before it, . stands for any single character, and ? makes the element before it optional in the extended form. A pattern matches only the whole name, an expression without anchors already matches a piece of the line.

Transforming in the stream: sed

The stream editor sed
Definition 8.1 (sed)

The command sed, short for “stream editor”, reads its input line by line. It puts each line into a buffer, applies to it, one after another, the commands that are in its first argument after the options, and then writes out the buffer. It does not change the files it reads.

Substituting: the s command
Definition 8.2 (The s command)

s/expression/replacement/ replaces the first match of the regular expression in every line with the replacement text. With the flag g after it, s/expression/replacement/g, it replaces all matches in the line. An & in the replacement text stands for the match found. Instead of the slash, any other character except the backslash and the newline may separate the three parts.

Selecting lines: line addresses, -n and p
Definition 8.3 (Line address, -n, p)

A line address in front of a command selects the lines it acts on: a line number, $ for the last line, /expression/ for all lines with a match or two line addresses with a comma in between for all lines from the one to the other. Without a line address, a command acts on every line. The option -n turns off the output after each line; then only the command p writes out lines.

Deleting lines: the d command
Definition 8.4 (The d command)

The command d deletes the buffer, outputs nothing and starts immediately with the next line. With a line address in front of it, exactly the selected lines drop out of the stream.

Groups and backreferences
Definition 8.5 (Backreference)

Each group of an expression remembers the piece it matched. In the replacement text of s, a backreference \1 to \9 inserts the piece of the first to the ninth group; the opening parentheses are counted from the left.

Editing the file itself: sed -i
Definition 8.6 (sed -i)

With the option -i, sed writes the result not to standard output but into a new file and then replaces the file it has read with this new file. If an extension follows directly after -i, such as -i.bak, sed keeps the old version under the name with this extension.

Calculating with columns: awk

The program awk: condition and action
Definition 9.1 (awk, rule)

The command awk runs a small program that is in its first argument after the options. The program consists of rules of the form condition {action}. awk reads its input line by line and checks every rule for each line in turn: if the condition is met, it carries out the action. If the condition is missing, the rule applies to every line; if the action is missing, awk writes out the line.

Fields: $1, $0, NF and -F
Definition 9.2 (Fields in awk)

awk splits every line into fields. $1, $2 and so on are the fields from the left, $0 is the whole line, and NF contains the number of fields, so $NF is the last field. Without an option, awk splits at sequences of spaces and tabs and skips them at the beginning and at the end of the line. With -F and a character, it splits at exactly this character.

Line number and conditions: NR
Definition 9.3 (NR, conditions)

NR contains the number of the line that awk is currently processing, counted from 1. Comparisons with ==, !=, <, <=, > and >= serve as conditions; you combine them with && for “and”, || for “or” and ! for “not”. field ~ /expression/ is met if the field contains a match for the regular expression. awk compares a field that looks like a number with a number by its value, otherwise as text.

Variables, sums and END
$ awk -F, 'NR > 1 {print $1, $2, $4 / $3}' laeufe.csv | head -n 3
↗
Definition 9.4 (Variable in awk, BEGIN, END)

A variable in awk is a name made of letters, digits and underscores, without a $ in front. Before its first assignment, it has the value 0 or the empty string, depending on how you use it. s += $3 adds field 3 to s, n++ increases n by 1. A rule with the condition END is carried out once after the last line has been read, one with BEGIN once before the first one is read.

Collecting values by name: associative arrays
Definition 9.5 (Associative array)

An associative array is a variable in awk that stores any number of values, each under a key of its own: s["Anna"] is the value under the key Anna. The key may be any text, including a field such as $2; a new key comes into being when it is first used, with the value 0 or the empty string like every new variable. for (k in s) executes a statement for each existing key, in an order that awk determines itself.

An analysis from start to finish

Which tool for what
Theorem 10.1 (Choosing a tool)

You select lines by content with grep, by number with head, tail or sed -n. You select columns with cut or awk. tr replaces characters, sed parts of lines. sort takes care of ordering, sort | uniq -c of counting identical lines. awk takes care of calculating with fields and collecting per group.

Building a pipeline step by step
Theorem 10.2 (Building step by step)

Build an analysis stage by stage. After each new stage, look at the intermediate result, with head for long outputs. Save an intermediate result that several questions need in a file.

Key points so far

The answer in three sentences

  1. You answer questions about a text file with small tools in a pipeline: select lines with grep, cut out columns with cut, order with sort, count with uniq -c, transform with tr and sed, calculate with awk.

  2. Instead of fixed words, regular expressions describe the form of the strings you are looking for, with wildcards, selections, anchors, repetitions and alternatives.

  3. The tools read line by line and character by character and know only characters, not meaning; their surprises follow from this, from 10 before 9 to the invisible carriage return.
