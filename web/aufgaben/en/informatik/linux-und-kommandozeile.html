Operating system, kernel and distribution

Exercise 1 ★ Who does what?

Classify each activity: Does it run in user mode or in kernel mode? Is a system call involved?

  1. A spreadsheet program calculates the average of 1 000 numbers that are already in main memory.

  2. The spreadsheet program saves the spreadsheet.

  3. The SSD's driver writes the blocks of the spreadsheet to the SSD.

  4. A browser asks for 200 MB of additional main memory.

Solution

(a) User mode, no system call. The numbers are already in the program's main memory, and adding and dividing are ordinary arithmetic instructions that every program may execute. The kernel is not involved.

(b) The spreadsheet program itself runs in user mode, but saving means getting data onto a storage device, and the program is not allowed to do that itself. It makes system calls, for example to open the file, to write and to close it. The actual work is then done by the kernel in kernel mode.

(c) Kernel mode. The driver is part of the kernel and addresses the device directly. It does not make a system call itself; instead, it carries out the request that came in with a system call in (b).

(d) System call. Which program may use which part of main memory is set only by the kernel; this is a privileged operation. So the browser asks the kernel via a system call, the kernel sets up the memory in kernel mode and tells the browser where it is.

Exercise 2 ★ Kernel or distribution?

Is the statement true? Justify each answer in one sentence.

  1. “Android is a Linux.”

  2. “Ubuntu and Kali Linux use the same kernel, so they are the same system.”

  3. “If you install Linux, you install a distribution.”

  4. “The package manager is part of the kernel.”

Solution

(a) In the strict sense, it is true: Android uses the Linux kernel. But Android is not a Linux distribution like Ubuntu, because around the kernel there are almost exclusively other programs. If you mean “Linux” in the everyday sense, that is, a system with a terminal and the usual tools, then Android is something different.

(b) False. Both use the Linux kernel, but each builds it itself in its own version, and everything around the kernel, the selection of programs, the default settings and the maintenance, differs. The same kernel alone does not make the same system.

(c) True. A kernel alone is not usable; what you download and install is always a distribution with a kernel, tools and a package manager.

(d) False. The package manager is an ordinary program of the distribution and runs in user mode. When it installs files, it makes system calls for this like any other program.

Exercise 3 ★★ Can a program get around the kernel?

A program in user mode tries three things, one after another: (1) to send data directly to the network card, (2) to change the entry point for system calls or the table of services so that a system call jumps into its own code, (3) to make a system call with a number that does not exist at all. What happens in each case, and why can the program not gain control of the computer by any of the three routes?

Solution

(1) Direct access to the network card is a privileged instruction. In user mode, the processor does not execute it; instead, it interrupts the program and hands over to the kernel, and the kernel terminates the program.

(2) Setting the entry point is a privileged instruction; such an attempt ends the same way as (1). The table of services is in a memory region of the kernel that programs in user mode are not allowed to write to; this attempt, too, is interrupted by the processor. The kernel set up both at startup in kernel mode, and nobody can change them from user mode.

(3) The system call itself is allowed. In the process, the processor jumps to the fixed entry point of the kernel, not to a location that the program chooses. There, the kernel looks up the number in its table, finds no service for it and returns an error code to the program. The program keeps running but has achieved nothing.

The reason for all three: There are exactly two ways to get into kernel mode, namely an interruption, for example when the processor traps a blocked instruction, or a system call, and both end up at locations that the kernel itself has set. Everything with which you could change these locations or reach the hardware directly is blocked in user mode.

Three ways to a Linux of your own

Exercise 5 ★ Choosing the right way

Use the decision tree to choose a way, and justify it in two sentences.

  1. Tom has a Windows 11 laptop and wants to learn Python next semester.

  2. In an IT security course, Sara wants to try out settings that can damage a system, and afterward start cleanly again each time.

  3. Ali is considering switching his old laptop entirely to Linux and wants to see beforehand whether Wi-Fi and graphics work.

  4. And you? Which way do you choose, and why?

Solution

(a) WSL 2. Tom needs a Linux for the command line and for programming, not for the hardware and not for a lab. With Windows 11, WSL 2 is set up in a few minutes, and he can use Windows and Linux at the same time.

(b) A virtual machine. Sara wants to try out things that can damage a system and afterward start cleanly again; that is exactly what a snapshot provides. In the process, the VM is separated from the host.

(c) The live USB stick. Only with it does Linux run directly on Ali's real hardware and have to control Wi-Fi and graphics itself. In a VM or in WSL 2, Linux would see only virtual devices and would reveal nothing about the real hardware.

(d) There is no wrong answer here, as long as the justification matches the question in the decision tree. If you read this series for programming or data analysis, take WSL 2; if you follow the Cybersecurity series, also set up a VM and start once from the stick.

Exercise 7 ★ A fact sheet for your computer

On Windows, collect four pieces of information about your computer. You do not change anything in the process.

  1. The edition and version of Windows: Settings $\to$ System $\to$ About, section “Windows specifications”.

  2. The installed memory: in the same place under “Device specifications”.

  3. The free space on drive C:, in File Explorer under “This PC”.

  4. Whether hardware virtualization is switched on, as in the example in subsection 3.4.

In a VM, Ubuntu 26.04 needs at least 6 GB of memory and 25 GB of space. Is your computer sufficient for this if Windows is to keep at least 8 GB for itself alongside the VM? Is Hyper-V available to you?

Solution

The values depend on your computer. This is how you evaluate them:

  • ⁠Memory. The VM needs 6 GB, and Windows is to keep 8 GB, so 14 GB together. With 16 GB, that is enough; with 8 GB, it is not, and then WSL 2 is the better way.

  • ⁠Space on C:. The VM needs 25 GB, the image another 6.5 GB. With less than about 35 GB free, it gets tight.

  • ⁠Virtualization. If Task Manager says “Enabled”, everything is ready. If it says “Disabled”, the setting must be switched on in the firmware; Section 7 shows how.

  • ⁠Hyper-V. If “Windows specifications” lists a Pro, Enterprise or Education edition, you can use Hyper-V; with Windows Home, you cannot. VirtualBox and WSL 2 run on all editions.

For comparison, this chapter's test computer: Windows 11 Home, 63.5 GB of memory. Memory and space are more than enough; Hyper-V as a feature of its own does not exist on Home. Nevertheless, Microsoft's hypervisor runs on this computer: systeminfo reports “A hypervisor has been detected”, because a security feature of Windows and WSL 2 use it.

Exercise 8 ★★ What the guest kernel is allowed to do

A guest kernel wants to (a) double a number in its VM's main memory, (b) set the location in its kernel to which a system call jumps, (c) write a block to its hard disk. Who does the work in each case, the processor directly or the hypervisor, and for whom does the result apply? Why would it be dangerous if the guest kernel were allowed to carry out (b) itself in the real kernel mode?

Solution

(a) The processor directly. Doubling a number in the VM's main memory is an ordinary arithmetic instruction on memory that the hypervisor has assigned to the VM anyway. It runs without a detour, and that is why the VM is almost as fast as real hardware.

(b) The setting applies only to the guest. In the operating mode for guests, the processor keeps a separate set of such settings for each guest; depending on the processor and the hypervisor, it makes the setting there directly, or it stops the guest and hands over to the hypervisor, which manages the setting for the guest. In both cases, system calls of the programs in the guest end up at the guest kernel, and the host's setting remains untouched.

(c) The hypervisor. A write access to a device is privileged. The hypervisor traps it and writes the block into the image file of the virtual hard disk; as a type 2 hypervisor, it uses a system call of the host for this.

If the guest kernel were allowed to carry out (b) in the real kernel mode, it would overwrite the entry point of the real processor. Then the system calls of all programs, including the programs of the host, would end up in its code, and it would have the whole machine in its hands. This is exactly what hardware virtualization prevents.

Exercise 9 ★★ Tracking snapshots

A VM goes through the following steps in order: install Ubuntu; snapshot “A”; create file x.txt; snapshot “B”; create file y.txt; delete x.txt; back to “B”; create file z.txt; back to “A”. Which of the three files exist at the end? How many differencing images did the hypervisor create along the way, and which ones did it discard?

Solution

At the end, none of the three files exists. The way there, with the model from Figure 6: A snapshot freezes the current image and creates a new differencing image; restoring discards the current differencing image and creates a new, empty one on top of the snapshot's state.

  1. Snapshot “A”: The base image with the freshly installed Ubuntu is frozen, and differencing image 1 is created.

  2. x.txt is written to differencing image 1.

  3. Snapshot “B”: Differencing image 1 is frozen and from now on belongs to “B”; differencing image 2 is created.

  4. Creating y.txt and deleting x.txt: both in differencing image 2.

  5. Back to “B”: Differencing image 2 is discarded, and differencing image 3 is created on top of the state of “B”. Now x.txt exists again, y.txt does not.

  6. z.txt is written to differencing image 3.

  7. Back to “A”: Differencing image 3 is discarded, and differencing image 4 is created directly on top of the base image. The state is the one directly after the installation: none of the three files.

So four differencing images were created and two were discarded (numbers 2 and 3). Number 1 is kept, because snapshot “B” still exists; you could return to it at any time and would find x.txt there.

Exercise 10 ★ What can a VM in NAT mode reach?

A VM runs in VirtualBox in NAT mode. Does it work, and why (or why not)? (a) The VM downloads updates from the internet. (b) A laptop on the same Wi-Fi network calls up a web page offered by a program in the VM. (c) The VM opens a web page offered by a program on a phone on the same Wi-Fi network.

Solution

(a) Works. The VM starts the connection itself; the hypervisor sends it on under the host's address, remembers the connection and passes the replies back.

(b) Does not work. The connection starts from outside. The other laptop does not know the address of the VM, and even a request to the host could not be assigned to any VM by the hypervisor, because none of them started it. Only a configured forwarding would change that.

(c) Works. Here, too, the VM starts the connection; to the phone, it looks as if the laptop were asking. Whether the destination is on the internet or on your own Wi-Fi network makes no difference.

Exercise 14 ★★ Where should the project go?

A fellow student stores his Python project with 2 000 small files under C:\Users\max\projekt and works in WSL in the folder /mnt/c/Users/max/projekt. He is surprised that every test run takes half a minute. Explain to him what is probably causing this, use the measured times from subsection 4.7 to estimate how much time it costs just to create all the files across the boundary once, and suggest a better place to store them. How does he then get at his files from Windows?

Solution

The project is on the Windows side, and the tests run in Linux. Every file access of the tests therefore travels as a message across the boundary of the VM to the file server on the Windows side and back. With many small files, this takes many times as long.

Estimate with the measurement from subsection 4.7: 37 seconds for 3 559 files is about 10 ms per file. Just creating 2 000 files across the boundary once therefore takes roughly

$$\textcolor{#1b7f4a}{2\,000\cdot10\ \mathrm{ms}}\textcolor{#15633a}{=}\textcolor{#c2410c}{20\ \mathrm{s}.}$$

This is only an estimate, because reading, writing and checking cost different amounts depending on the kind of access; but it shows that half a minute per test run can easily arise from the boundary alone.

Better: Move the project into the Linux part, for example to /home/max/projekt, and work there. From Windows, Max then reaches it in File Explorer under “Linux” or at \\wsl.localhost\Ubuntu-26.04\home\max\projekt. Now the way across the boundary is taken only when he opens a file from Windows, not on every test run.

Storage device, image and checksum

Exercise 15 ★ A checksum on both sides

On Windows, use Notepad to create a text file with a line of your choice. Calculate its checksum in PowerShell with Get-FileHash. If you have set up WSL 2, also calculate it in Linux with sha256sum; there, the path begins with /mnt/c. Do the values match? Then change a single character, save and calculate the checksum again.

Solution

Both tools read the same bytes of the file and apply the same method, SHA-256, to them; the values therefore match, on Windows in uppercase letters, on Linux in lowercase letters. If the file is, for example, at C:\Users\<Name>\Documents\notiz.txt, the command in Linux is sha256sum /mnt/c/Users/<Name>/Documents/notiz.txt. After changing a single character, the value is completely different, as in the example “One letter different”.

If the values did not match before the change, the two tools did not read the same file, for example because Notepad had not yet saved the file or because two files with similar names exist. Checksums compare bytes, not the visible text: An invisible difference, such as an additional space at the end of a line, results in a different value.

Exercise 16 ★★ How much does part of the value reveal?

  1. In the two checksums from the example “One letter different”, count the positions at which both values have the same digit. How many equal positions do you expect on average for two random values, and why?

  2. Someone compares only the first six characters. Roughly how many attempts does an attacker need to find a forgery whose checksum begins with the same six characters? How many would it be if all 64 characters were compared?

Solution

(a) The two values

99fe677717755bcd765dabb7092a68d674ecb79d8e1885a042ca5c90157c1098
bcfef736955e8b5f649a111842d4a17f4d9b8c9bf1ed32ea6ef7c179d102bdd5

match at 5 of the 64 positions. If two values are unrelated, each position is independently one of the 16 hexadecimal digits, and the probability that they match at a given position is $1/16$. On average, you therefore expect $\textcolor{#1b7f4a}{64\cdot\frac1{16}}\textcolor{#15633a}{=}\textcolor{#c2410c}{4}$ equal positions. A count of 5 is a perfectly ordinary random result; the two checksums behave like two unrelated values, although the files differ in only one letter.

(b) Six hexadecimal digits can take $\textcolor{#1b7f4a}{16^6}\textcolor{#15633a}{=}\textcolor{#c2410c}{2^{24}}\textcolor{#15633a}{=}\textcolor{#c2410c}{16\,777\,216}$ different values. An attacker who keeps varying a forgery at an unimportant place therefore hits a checksum with the same six initial characters after about 17 million attempts, which for a computer is a matter of fractions of a second to seconds. For all 64 characters, the attacker would need about $\textcolor{#1b7f4a}{16^{64}}\textcolor{#15633a}{=}\textcolor{#c2410c}{2^{256}}\textcolor{#15633a}{\approx}\textcolor{#c2410c}{1.16\cdot10^{77}}$ attempts; no conceivable computer can manage that. A partial comparison therefore protects against random errors, but not against intent.

Exercise 17 ★ Does the image fit on the stick?

An image is 6 482 409 472 bytes in size. Windows displays the sizes 3.72 GB, 7.45 GB and 14.9 GB for three sticks. Which sticks does the image fit on? To find out, convert the size of the image into the same unit that Windows uses.

Solution

In the unit that Windows uses, the image has

$$\textcolor{#1b7f4a}{\frac{6\,482\,409\,472\ \mathrm{bytes}}{1\,073\,741\,824\ \mathrm{bytes/GiB}}}\textcolor{#15633a}{=}\textcolor{#c2410c}{6.04\ \mathrm{GiB}.}$$

So it does not fit on the stick with 3.72 (a stick labeled 4 GB), but it does fit on the sticks with 7.45 (8 GB) and 14.9 (16 GB). If you instead compare 6.48, the size the publisher states for the image, with 7.45 from the Windows display, you arrive at the same result here, but you are comparing two different units; in close cases, this leads you astray.

Exercise 18 ★★ What helps against the swapped server?

In the example with the mirror server, the image and SHA256SUMS have the same flaw. Which of the following measures would have uncovered the forgery, and which would not? (a) sha256sum -c instead of comparison by eye, (b) SHA256SUMS from https://releases.ubuntu.com, the image from the mirror server, (c) downloading the image and the list twice, (d) checking the signature SHA256SUMS.gpg.

Solution

(a) Does not uncover the forgery. sha256sum -c only compares more precisely than the eye; since the image and the list match each other, it reports OK.

(b) Uncovers it. The genuine list from https://releases.ubuntu.com contains the checksum of the genuine image; the forged image has a different one, and the comparison reports FAILED or False. The prerequisite is that the official server itself has not been tampered with.

(c) Does not uncover it. The mirror server delivers the same forged file and the same forged list both times.

(d) Uncovers it. Only someone who has Ubuntu's secret key can produce a valid signature over SHA256SUMS; the attacker does not have it. A forged list is therefore noticed when the signature is checked, provided that you check with Ubuntu's genuine verification key.

Exercise 20 ★★ Where does the chain break?

A computer has Secure Boot switched on. At which link of the chain from Figure 10 does booting stop, or does the system start? (a) Someone has changed a byte in GRUB on the stick. (b) The stick contains a kernel that nobody has signed. (c) An Ubuntu stick is plugged into a computer whose firmware does not contain Microsoft's verification key for third-party boot programs. (d) An Ubuntu stick is started via the boot menu. Does (d) trigger a recovery key prompt on an encrypted Windows?

Solution

(a) Booting stops at the transition from shim to GRUB. shim checks GRUB's seal with Canonical's verification key; after the change, the seal no longer matches.

(b) Booting stops at the transition from GRUB to the kernel, because GRUB finds no valid seal on the kernel. This is exactly why you have to switch off Secure Boot for a kernel without a signature, such as that of Kali Linux.

(c) The very first link fails: The firmware does not know the verification key with which Microsoft signed shim, and does not start shim. Some computers come with their firmware set up like this. The remedy is a setting in the firmware that allows this key; this is a change to the boot chain, for which the recovery key must be backed up beforehand.

(d) The system starts: firmware, shim, GRUB and kernel are suitably signed. A recovery key prompt is normally not to be expected at the next start of Windows. The boot menu changes neither the Windows Boot Manager nor a setting of the firmware; at the next start, the boot chain of Windows is the same as before. Only on older computers with a security chip of version 1.2 can a changed boot order trigger the prompt. Nevertheless, you have backed up the key, in case a computer behaves differently.

Exercise 22 ★★ Why “Erase disk” is harmless in the VM

Using the concepts guest, hypervisor and virtual hard disk, explain why choosing “Erase disk and install Ubuntu” in the VM does not endanger the files of Windows. Which file on the host does the guest actually change in the process? What would have to happen for the guest to be able to write to the host's SSD after all?

Solution

The guest sees only the hardware that the hypervisor simulates for it. As its hard disk, it sees the virtual hard disk, and on the host, that is an ordinary file, in VirtualBox by default ubuntu-labor.vdi in the folder VirtualBox VMs\ubuntu-labor of the Windows user. When the installer “erases the whole disk”, the guest kernel writes new partitions and file systems to this virtual hard disk. Each of these write accesses is a privileged device access that the hypervisor traps and writes into this one file. The host's SSD with Windows is not a device of the VM; the guest does not even know that it exists.

For the guest to be able to write to the host's SSD, you would have to assign the SSD to it explicitly as a device; VirtualBox can do that, but only via a setting for experts that you never use here. The guest could also get at individual files of the host if you share a folder of the host with it; this, too, happens only if you explicitly ask for it. Otherwise, the only remaining possibility would be a bug in the hypervisor itself that breaks the separation between guest and host.

Exercise 24 ★★ Tracing the overlay

The lower layer of an overlay contains the files a, b and c; the upper layer is empty. The following happens in sequence: a is changed, b is deleted, d is newly created, d is changed. What is then in the upper layer, what is in the lower one, and which files do the programs see? What do they see after a restart?

Solution

Step by step:

  • Changing a: The overlay copies a to the upper layer and changes the copy there.

  • Deleting b: A marker is created in the upper layer that hides b.

  • Creating d: d is created only in the upper layer.

  • Changing d: The file is already in the upper layer and is changed there; no copy is needed.

Afterward, the upper layer contains the changed copy of a, the marker for b and the changed file d. The lower layer contains a, b and c, unchanged. The programs see a in the changed version, c and d; they do not see b. After a restart, the upper layer is empty: The programs again see a in the original version, b and c, and d does not exist.

Exercise 25 ★ When main memory becomes full

A computer with 8 GB of memory is running the live system. You download a 5 GB file into your home folder. Why can the live system get into difficulties in the process, although the USB stick still has space and the internal SSD has 300 GB free?

Solution

The home folder is in the overlay, and everything you save there ends up in the upper layer, that is, in the tmpfs in main memory. The 5 GB of the downloaded file therefore occupy 5 GB of main memory, in addition to what the running system, the browser and the download itself need. With 8 GB, main memory becomes scarce or runs full, or the tmpfs reaches the maximum size that was set when it was mounted. Then the download aborts with an error, or the whole system becomes sluggish.

The free space on the stick does not help, because the live system without persistence writes nothing there; the lower layer is read-only. The free space on the SSD does not help, because the SSD is not mounted. In the live system, you therefore save large files on a second USB stick or upload them directly to cloud storage.
